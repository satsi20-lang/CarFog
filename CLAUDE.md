# CarFog (dry_fog_app) — правила для работы

## Тесты (обязательно для всех задач)

Полный прогон занимает около 6–7 минут, быстрый — от десятков секунд. Поэтому:

1. **Во время работы** — только `tool/test_quick.sh [файлы…]`: `flutter analyze` + тесты,
   связанные с изменёнными файлами (по имени и по импорту), без меток `golden` и `slow`.
   Без аргументов берёт файлы из `git diff origin/main...HEAD` и незакоммиченные.
   Связь не найдена — запускаются все быстрые тесты.
2. **Полный прогон** — `tool/test_full.sh` (analyze + весь `flutter test` одним прогоном +
   Kotlin, если менялся `android/`) — **только в контрольных точках**:
   - перед пушем готовой части;
   - перед слиянием в main;
   - перед сборкой APK для установки.
3. **golden-тесты** (метка `golden`, эталоны в `test/goldens`) — только если менялись
   экраны, виджеты, бренд, ассеты (`lib/screens`, `lib/widgets`, `lib/brand`, `lib/ui`,
   `assets/`). `test_quick.sh` сам включает `golden` и `layout` в этом случае.
4. **Kotlin-тесты** — только если менялась папка `android/`
   (`cd android && ./gradlew :app:testDebugUnitTest`, нужен `JAVA_HOME` из Android Studio jbr).
5. **Только документы и миграции** (`docs/`, `supabase/`, `*.md`) — тесты приложения не нужны.
   Тесты Deno/SQL-функций запускаются по их собственным правилам.
6. **Слияние без новых правок** — не гонять тесты заново: сравнить деревья
   (`git rev-parse <merge>^{tree}` с уже проверенным коммитом); совпало — проверено.
7. **Никогда не запускать полные прогоны параллельно** в нескольких рабочих копиях:
   тайминговые тесты (метка `slow`, например «20 000 строк < 1500 мс») под нагрузкой дают
   ложные красные.

Метки (`dart_test.yaml`): `golden` — сравнение с эталонами; `layout` — раскладка экранов в обоих
профилях; `slow` — долгие или тайминговые. Без метки — быстрые. Метка ставится первой строкой
файла: `@Tags(['slow'])` и `library;`.

`flutter analyze` должен оставаться чистым: допускаются только два старых замечания
(`_currentTemp` в `treating.dart`, const-конструктор в `fog_background.dart`) — `tool/_analyze.sh`
их знает и ругается на любые другие.

## Другие правила проекта

- Эталоны Syoung (`test/goldens/syoung`, `test/syoung_golden_test.dart`) и прежние эталоны не
  менять без отдельного «да» владельца. Новые экраны — новые эталоны отдельными файлами.
- Секреты, токены, PIN, коды запуска, подписанные ссылки — не писать в файлы, коммиты, логи
  и отчёты (в тестах — заведомо тестовые значения).
- В облако (Storage, `app_releases`, кольца), на планшеты (установка), в базу и Supabase —
  только по явному «да» владельца в этой задаче. Одно «да» не распространяется на следующие.
- Пуш — только по просьбе или явному разрешению; в `main` не вливать без «да».
- Порты шины (`ttyS1`, `ttyUSB0-2`) не открывать без необходимости; на шину не писать.
- Версию в `pubspec.yaml` меняет только отдельный коммит по задаче на релиз.
- Коммиты оканчиваются строками:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` и
  `Claude-Session: https://claude.ai/code/session_011vfHRkygLhL5in9yveoQ4U`.
- Владелец — новичок: отчёты простыми словами, сначала вывод.
