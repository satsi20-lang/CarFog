# Опись: видео заставки на SD-карте (до плейлиста через портал)

Дата: 2026-11-07, ветка `video-playlist` от main 9f57f27. Только чтение кода; на планшеты не заходили.

## Вывод
- Сейчас видео ищется **только** в папке `vid` в корне тома: `<том SD>/vid`, затем `/storage/emulated/0/vid` и `/storage/self/primary/vid`. Берётся первая папка, где есть хоть один файл `.mp4/.mkv/.webm`. Все файлы играют по кругу, в алфавитном порядке пути.
- В приложении **нет встроенного видео CaRFog** (в `assets/` только логотип и QR). Сейчас «ничего нет» = заставка с логотипом и QR без видео. ТЗ п.2.5 («играет встроенное видео») без файла не выполнить — см. вопрос владельцу.
- В манифесте уже есть `MANAGE_EXTERNAL_STORAGE` (даёт прямой доступ к файлам). Если оно выдано (на заводе — `appops set ... allow`, приложение при старте и само просит), приложение может читать, писать и **удалять** файлы в `/vid`. Новых разрешений для плейлиста не нужно.
- Новые видео хранить в папке самого приложения на SD (`Android/data/ee.carfog.dryfog/files/videos` на съёмном томе) — для неё разрешение вообще не нужно и она не смешивается с ручными файлами. Ручные файлы из `vid` показывать как `sd_local`.

## Как сейчас работает
| Что | Где | Факт |
|---|---|---|
| Поиск | `lib/screens/standby.dart` `_scanVideos` | тома через `StorageService.listVolumeRoots()` (канал `com.carfog.dryfog/storage`, `MainActivity.kt` `listVolumeRoots`: съёмные тома первыми, встроенная память последней) → `<том>/vid`; `Directory.listSync`, фильтр по расширению `.mp4/.mkv/.webm`, `sort()` |
| Когда играет | `standby.dart` | 30 с без касания на заставке → `_startVideo`; касание → `_stopVideo` и возврат на заставку (второе касание — уходит дальше) |
| Плеер | `video_player` ^2.13.0 (ExoPlayer), `VideoPlayerController.file` | один файл — `setLooping(true)`; несколько — переход на следующий по `isCompleted`, флаг `advancing` против двойного срабатывания |
| Битый файл | `_playVideo` | ошибка `initialize` или `hasError` → следующий; если подряд не открылись все — возврат на заставку |
| Звук | `config.standbyVideoSound` (по умолчанию false) → `standbyVideoVolume` 0/1, `setVolume` на каждом ролике; тумблер в сервисном меню «Звук видео ожидания», сохраняется сразу |
| Список обновляется | только в `initState` экрана заставки | карту вставили/сменили — виден после повторного входа на экран заставки |
| Нет карты / папки | `_scanVideos` | `Directory.exists` = false → плейлист пуст → `_startVideo` ничего не делает, остаётся заставка. Ошибок нет, исключения не ловятся только вокруг `listSync` (при потере карты на ходу — возможна ошибка; в плане: оборачивать) |

## Права Android 13 (IXP101M1 и Syoung, оба Android 13)
- `MANAGE_EXTERNAL_STORAGE` объявлено в манифесте (причина — файлы произвольного расширения, раньше `.lmxb`). `MainActivity.requestAllFilesAccessIfNeeded` просит его при старте, если не выдано.
- С ним: запись/удаление в `<том>/vid` разрешены. Без него: чтение `listSync` в `/vid` может не работать вовсе (Scoped storage), удаление — тем более.
- Папка приложения `getExternalFilesDirs` (`Android/data/<пакет>/files`): запись и удаление **без разрешений** на API 33 (своя папка). Нужна именно запись для скачивания.
- Проверить вживую (не проверялось, планшеты не трогали): выдан ли `MANAGE_EXTERNAL_STORAGE` на CARFOG-001 и на Syoung; видна ли карта как съёмный том (`StorageVolume.isRemovable`). Команда: `adb shell appops get ee.carfog.dryfog MANAGE_EXTERNAL_STORAGE`.
- Новый Kotlin-метод нужен только один: список папок приложения на томах (`getExternalFilesDirs`) + свободное место. Это не разрешение, а чтение путей. `path_provider` в зависимостях нет и не добавляю (ещё один плагин и Gradle-правки) — расширяю существующий канал `storage`.

## Решения для плейлиста
1. **Где хранить новые**: `<съёмный том>/Android/data/ee.carfog.dryfog/files/videos/<video_id>.mp4`. Нет съёмного тома — не качаем (в отчёт `failed:no_sd`), встроенную память не занимаем (мало места, ТЗ говорит про SD).
2. **Ручные файлы**: сканировать `<том>/vid` (как сейчас) как `sd_local`, поле `local_name` = имя файла. «Можно удалить» = есть `MANAGE_EXTERNAL_STORAGE` (`Environment.isExternalStorageManager`) и файл доступен на запись. Иначе в портале «удалить нельзя».
3. **Чтобы не сломать то, что работает**: сейчас все ручные видео играют. Если новые `sd_local` создавать с `play=false`, после обновления заставка у клиентов с ручными файлами «замолчит». Поэтому строки `sd_local` создаются с `play=true` (решение исполнителя; ТЗ говорит «по умолчанию false» про новые загруженные, они так и остаются).
4. **Старый путь не удаляем**: если облако ещё не сообщило набор (нет сети, `videos_rev` не получен), играет прежний поиск `vid` — как сейчас.
5. **Одна общая очередь на заставке**: порядок «по дате добавления» — у загруженных `created_at` из облака; у ручных — время изменения файла; ручные раньше облачных не ставим, общий сортировочный ключ — дата.
6. **Встроенного видео нет**: пустой набор = прежняя заставка логотип/QR (без видео). Файл ролика в приложение положить может только владелец (нужен готовый mp4 1280×800 и 1080×1920).
