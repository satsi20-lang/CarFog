# Киоск через Device Owner и Lock Task (1.10.4)

Проверено 11.10.2026 на старом тестовом планшете rk3568 и на CARFOG-100
(Syoung SY156-A510, rk3562, Android 13, userdebug): назначение, блокировка,
выход техника, обновление (`adb install -r` и штатный скрипт с откатом),
холодный старт, полный платный цикл под блокировкой, снятие. Особенности
CARFOG-100 — в отдельном разделе ниже.

Всё описанное ниже работает только после назначения Device Owner. Вкладка
«Киоск» показывает «Device Owner назначен» или «Device Owner не назначен».

* **Без Device Owner** — всё как раньше: старый тумблер «Киоск-режим»
  (роль домашнего экрана через HOME-алиас, `docs/kiosk_mode.md`) и кнопка
  «Открыть системный рабочий стол»; раздел Device Owner неактивен.
* **С Device Owner** — старый тумблер и кнопка рабочего стола скрыты:
  роль домашнего экрана закрепляет политика, остаётся один переключатель
  «Блокировка включена». Значение старого тумблера при этом сохраняется и
  снова действует после снятия Device Owner.

## Что это даёт

Device Owner — роль «владелец устройства»: приложению разрешено управлять
системными политиками. Lock Task — закрепление экрана за одним приложением.

Вместе, при включённой блокировке:

* шторка (свайп сверху) не открывается — строка состояния отключена;
* навигация не работает: Home, «Недавние» и меню питания (долгое нажатие)
  не выводят из приложения; свайп снизу показывает только неактивную
  кнопку «Назад» (на CARFOG-100 панели навигации нет вовсе);
* роль домашнего экрана закреплена за приложением политикой и переживает
  обновление APK;
* после обновления и после перезагрузки приложение поднимается само и
  снова закрепляет экран — без касаний.

Кнопку питания Lock Task не перехватывает. На обычном планшете короткое
нажатие гасит экран (это не выход из приложения); на CARFOG-100 оно
обесточивает планшет — см. ниже.

## Условия

1. На планшете **нет аккаунтов** (`adb shell dumpsys account` → `Accounts: 0`).
2. **Один пользователь** (`adb shell pm list users` → только `0:Owner`).
3. Device Owner ещё не назначен (`adb shell dumpsys device_policy` — нет
   строки `Device Owner:`).
4. Установлена версия с приёмником `CarfogAdminReceiver` (1.10.4+32 и новее
   из этой ветки).

Если аккаунт или второй пользователь есть — назначение откажет; помогает
только сброс до заводских.

## Как назначить

1. Подключиться к планшету по adb.
2. Выполнить:

   ```
   adb shell dpm set-device-owner ee.carfog.dryfog/com.example.dry_fog_app.CarfogAdminReceiver
   ```

   Ответ при успехе: `Success: Device owner set to package ee.carfog.dryfog/...`.
3. Проверить: `adb shell dumpsys device_policy | grep -A2 "Device Owner"` —
   там `admin=ComponentInfo{ee.carfog.dryfog/com.example.dry_fog_app.CarfogAdminReceiver}`.

`ee.carfog.dryfog` — идентификатор приложения, `com.example.dry_fog_app` —
пакет классов (namespace); они разные, команда должна содержать оба именно
так.

## Как включить и выключить блокировку

1. Сервисное меню (долгое нажатие в левом верхнем углу заставки или экрана
   «Временно не работает», PIN) → вкладка «Киоск».
2. Раздел «Device Owner (Lock Task)» → переключатель «Блокировка включена».
3. Включение сохраняется и применяется при каждом старте приложения.
   Выключение снимает закрепление, возвращает шторку и навигацию, роль
   домашнего экрана возвращается к тумблеру «Киоск-режим». Если экран был
   поднят как домашний, а старый тумблер выключен, экран через ~1 с
   пересоздаётся (сервисное меню закрывается).

## Три кнопки техника (там же, за PIN)

1. **«Выйти из блокировки на 10 минут»** — закрепление снято, шторка и
   навигация работают. Через 10 минут блокировка возвращается сама
   (таймер не зависит от того, что открыто на экране). Если приложение за
   это время перезапустилось — блокировка включается сразу.
2. **«Открыть настройки на 10 минут»** — то же, плюс сразу открываются
   системные настройки (например, включить беспроводную отладку). Через 10
   минут приложение само выходит на передний план и закрепляет экран.
3. **«Снять Device Owner»** — два подтверждения. Снимает закрепление, все
   политики киоска и саму роль Device Owner. Приложение остаётся на экране
   (через ~1 с поднимается заново — сервисное меню закрывается, экран
   начинается с выбора языка). Назначить снова — только командой из раздела
   «Как назначить».

Каждое включение, выход, снятие и ошибка пишутся в журнал приложения (тег
`Kiosk`), без PIN и токенов.

## Аварийный выход без приложения (root)

Нужен, если приложение не открывается или PIN недоступен, а планшет
закреплён. Требуется adb и root (`su`). Проверено на rk3568.

Пути без root **не работают**:

* `dpm remove-active-admin …` → `SecurityException: Attempt to remove
  non-test admin`;
* `am task lock stop` → закрепление остаётся;
* `am force-stop ee.carfog.dryfog` → Android не останавливает приложение —
  владельца устройства.

Последовательность:

1. Удалить файлы политик устройства:

   ```
   adb shell "su 0 rm /data/system/device_owner_2.xml /data/system/device_policies.xml"
   ```

2. Перезагрузить: `adb reboot`.
   После загрузки Device Owner нет, закрепления нет, шторка и навигация
   работают. Приложение всё ещё открывается кнопкой «Домой» (роль
   домашнего экрана хранится отдельно от политик).
3. Если беспроводная отладка выключилась после перезагрузки — включить её
   в «Настройки → Для разработчиков» (теперь доступны).
4. Вернуть системный рабочий стол:

   ```
   adb shell "su 0 pm disable ee.carfog.dryfog/com.example.dry_fog_app.KioskHomeAlias"
   ```

   Без `su` команда отказывает (`Shell cannot change component state`).
5. Проверить: `adb shell dumpsys device_policy` — нет `Device Owner:`,
   `Enabled Device Admins` пуст.

Что не трогается: данные приложения (настройки, журнал, мастер-код) и
системные настройки — проверено сравнением до и после. Признак «блокировка
включена» в приложении сохраняется: если позже снова назначить Device Owner,
блокировка включится при первом же появлении приложения на экране.

## Обновление APK

1. Android при замене пакета убивает процесс и возвращает HOME-алиас в
   состояние из манифеста (выключен).
2. Приложение ловит `MY_PACKAGE_REPLACED`: восстанавливает алиас и
   политики и само запускается (Device Owner вправе запускать экран из
   фона).
3. При штатном обновлении (корневой скрипт `update_script.dart`) экран
   поднимают ещё двое: сама система (роль домашнего экрана) и `am start`
   из скрипта. Это безопасно: MainActivity — `singleInstance`, повторные
   запуски система отдаёт уже живому экземпляру, второй экземпляр не
   появлялся ни разу; на крайний случай его закрывает защита в
   `MainActivity.onCreate`.
4. Пока процесса нет, система десятки раз подряд пытается запустить
   домашний экран (замер на CARFOG-100: ~60 попыток за 1,8 с при установке,
   43 при откате). Это поведение Android, вреда нет.
5. `cmd role add-role-holder HOME` из скрипта не конфликтует с политикой
   Device Owner: держатель роли и закреплённая HOME-активность — одно и то
   же приложение.
6. Экран снова закреплён через **2,5–4 с** после замены пакета (замеры:
   rk3568 — 1,8 и 1,9 с; CARFOG-100 — 3,9 с `adb install -r`, 3,1 с
   установка скриптом, 2,5 с автоматический откат). Device Owner,
   отключённая шторка и роль домашнего экрана сохраняются без повторной
   настройки.

## Перезагрузка

1. Система сама запускает приложение как домашний экран (~1–2 с после
   окончания загрузки).
2. Приложение закрепляет экран: через 2,5 с (rk3568) и через 3,8–4,0 с
   (CARFOG-100) после окончания загрузки. Чёрного экрана не было ни разу.
3. Беспроводная отладка Android после перезагрузки выключается — включать
   через «Открыть настройки на 10 минут». Сетевой adb (5555) после
   перезагрузки тоже закрыт — см. «Сетевой adb».
4. **На CARFOG-100 `adb reboot` не делать никогда**: программная
   перезагрузка даёт чёрный экран. Перезагрузка — только владелец, холодным
   выключением кнопкой питания.

## Как снять Device Owner

Обычный путь — кнопка «Снять Device Owner» (см. выше). Аварийный — через
root (см. выше). Сброс до заводских тоже снимает, но стирает всё.

## Сетевой adb (с 1.10.6)

Порт adb в сети по умолчанию закрыт, открывается только на время работы.
Для техника — `docs/technician_guide.md`, раздел 8.

**Почему так.** `ro.adb.secure` на этой прошивке (userdebug) не задано, и
adbd не проверяет ключ клиента — ни на 5555, ни на беспроводной отладке
(TLS: в adbd путь `adbd_tls_verify_cert` → «auth not required», код
сопряжения не нужен). Файла `/data/misc/adb/adb_keys` нет. Пока порт
открыт, любой в той же сети получает shell, а через `/system/xbin/su` —
root. Ключ появится только с прошивкой `ro.adb.secure=1` (вопрос к
поставщику). USB-отладка на SY156-A510 не работает: OTG-контроллер
`fe500000.usb` в режиме host, `/sys/class/udc` пуст.

**Кто открывает порт.** Три свойства (adbd читает порт только при своём
запуске):

| Свойство | Действие | После перезагрузки |
|---|---|---|
| `persist.internet_adb_enable=1` | правило `init.rk30board.rc`: `service.adb.tcp.port=5555` + `restart adbd`; при `=0` — порт `0` | остаётся |
| `service.adb.tcp.port` | adbd читает первым | пропадает |
| `persist.adb.tcp.port` | adbd читает, если `service.*` пусто | остаётся |

Ни в одном `build.prop` этих свойств нет — после сброса до заводских порт
закрыт. На CARFOG-100 до 1.10.6 были `internet_adb_enable=1` и
`persist.adb.tcp.port=5555`.

**Что делает приложение** (`lib/services/adb_network_service.dart`,
команды — `lib/models/adb_exposure.dart`):

* Тумблер «Сетевой ADB на 30 минут»: снимает оба `persist.*` (дожидаясь,
  пока сработает правило init для `internet_adb_enable`, иначе оно
  перетрёт порт), ставит `service.adb.tcp.port=5555` и перезапускает adbd.
  Порт не переживает перезагрузку. Через 30 минут закрывается: все три
  свойства в `0`/пусто, перезапуск adbd. Срок хранится в настройках —
  перезапуск приложения внутри окна (`adb install`) окно не обрывает.
* При старте и раз в 5 мин (раз в 1 мин, пока что-то открыто): порт,
  открытый вне окна, закрывается сразу (`startup` / `outside_window`).
* Беспроводная отладка — тот же срок 30 минут с момента, когда приложение
  её увидело, затем `settings put global adb_wifi_enabled 0`.
* Тумблер показывает только 5555; беспроводная отладка — отдельной строкой
  со своим отсчётом. Выключение тумблера гасит оба.
* Состояние для слепка — по слушающему сокету (`/proc/net/tcp{,6}`,
  состояние `0A`), свойства только объясняют причину; `adb_network_detail`
  содержит порт, источник, TLS и признак расхождения.

Любое открытие adbd обрывает текущие adb-сессии (и по 5555, и TLS) — это
ожидаемо.

## Ограничения

* Назначить Device Owner можно только на планшете без аккаунтов и с одним
  пользователем; иначе — сброс до заводских.
* Без root аварийного выхода нет: если приложение не открывается и PIN
  потерян, остаётся только сброс до заводских. Аварийный выход через root
  требует adb, а сетевой adb открывается только из приложения (USB на
  SY156-A510 не работает) — на CARFOG-100 при мёртвом приложении остаётся
  только сброс до заводских; как его сделать без приложения и без USB,
  уточняется у Syoung.
* Во время временного выхода кнопка «Назад» закрывает экран приложения,
  «Домой» сразу поднимает его снова (короткое мигание).
* При снятии Device Owner или выключении блокировки экран приложения
  пересоздаётся (если он был поднят как домашний экран): ~1 с, сервисное
  меню закрывается. Если процесс приложения умрёт в эту секунду, Device
  Owner останется назначенным при выключенной блокировке — кнопку можно
  нажать ещё раз.

## CARFOG-100 (Syoung SY156-A510): особенности

1. **Панели навигации нет вовсе** — в прошивке только строка состояния.
   Свайп снизу ничего не показывает ни под блокировкой, ни без неё (в том
   числе во время выхода техника).
2. **Короткое нажатие физической кнопки питания (задняя стенка)
   обесточивает планшет** — это не сон и не штатное выключение Android
   (при загрузке — «not cleanly shutdown» и проверка файловой системы).
   Lock Task её не перехватывает. После включения приложение поднимается
   само и закрепляет экран (~4 с после загрузки), данные сохраняются.
   Кнопку лучше закрыть физически.
3. **Не слать `adb shell input keyevent KEYCODE_POWER`**: экран гаснет,
   процессор засыпает вместе с Wi-Fi (Doze), adb пропадает, команда
   пробуждения до планшета уже не доходит — будить только физической
   кнопкой. Сам экран не гаснет: тайм-аут «никогда», приложение держит
   `KEEP_SCREEN_ON`. «Не выключать при зарядке» здесь не действует: драйвера
   батареи нет, Android не видит зарядку.
4. Шторка и дополнительные вендорские панели (Internet, Bluetooth и т. п.)
   под блокировкой не открываются — ни первым, ни вторым свайпом.
5. Назначение Device Owner на обычное (не системное) приложение прошло без
   отказа.
6. Файлы политик лежат там же, что и на rk3568
   (`/data/system/device_owner_2.xml`, `/data/system/device_policies.xml`),
   аварийный путь через root применим (сами файлы на CARFOG-100 не удаляли).
7. Полный платный цикл под блокировкой: блокировка не слетает, защиты не
   срабатывают, сводка цикла пишется как обычно.

## Обесточивание: что сохраняется

Проверено по коду в 1.10.4+38 (на CARFOG-100 одно внезапное отключение —
данные целы).

* С fsync сразу: все настройки приложения и облачная очередь/история
  событий (`SharedPreferences` через `commit`), признак «выведен из
  обслуживания» (`OutOfServiceStore`: fsync + атомарная замена), признак
  блокировки киоска, признак аварии.
* С 1.10.4+38 тоже с fsync: журнал приложения (пачка раз в 1 с), базовая
  точка и месячная история счётчика энергии, сброс признака аварии,
  отложенный пакет диагностики, служебные файлы обновления и сигнал
  здоровья.
* Сводка цикла уходит в событие завершения сеанса (облачная очередь, с
  fsync) и строкой в журнал.
* Может потеряться: последняя секунда журнала (ещё в памяти); недокачанный
  APK обновления (докачивается заново, перед установкой проверяется).

## Не проверено

1. Тихая установка через Тулбокс.
2. Облачный релиз целиком (скрипт обновления проверен запуском из adb, без
   выхода из cgroup приложения).
3. Долгое нажатие физической кнопки питания CARFOG-100 (короткое уже
   обесточивает).
4. Аварийный выход через root на самом CARFOG-100.
