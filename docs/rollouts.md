# Раскатка обновления по кольцам (R3)

Миграция: `supabase/migrations/20261006000000_r3_rollouts.sql` (выполняет только
владелец, в SQL Editor). Проверка прав: `supabase/tests/rls_rollouts.sql`
(запускать на копии базы, в конце откат).

## Как устроено

* **Кольца** `test` → `early` → `all`. Кольцо и часовой пояс аппарату назначает
  владелец вручную: `select device_set_ring_tz('<id>', 'early', 'Europe/Tallinn');`
  (по умолчанию кольцо `all`, пояс `UTC`). Переход к следующему кольцу — только
  кнопкой владельца (создать раскатку на следующее кольцо и активировать), по
  таймеру ничего не происходит.
* **Раскатка** — строка в `rollouts`: релиз + кольцо + окно + статус. Создаётся
  в статусе `paused`.
  * создать: `select rollout_create('<id релиза>', 'test');` (окно по умолчанию
    02:00–05:00, задержка до 30 минут);
  * запустить / остановить: `select rollout_set_status('<id раскатки>', 'active' | 'paused' | 'done' | 'cancelled');`
* **Целевая версия.** Аппарат не получает команду. Сервер в ответе `device_poll`
  отдаёт поле `target` (`rollout_id`, `release_id`, `version_name`, `version_code`),
  когда для **этого** аппарата «пора»: время сервера в поясе аппарата внутри окна
  02:00–05:00, сдвинутого на детерминированную задержку 0–30 минут (по паре
  аппарат + раскатка, чтобы не качали все разом). Часы планшета не используются.
  Пока окно закрыто, `target = null`. Установленная версия берётся из
  `devices.app_version` (часть после `+`; нет кода — 0). Цель, которая не новее
  установленной, не отдаётся.
* **Что делает аппарат.** Получив цель, запускает тот же `update_app`-код
  (`UpdateService.startUpdate`, источник `rollout`): все проверки, скрипт, откат
  без изменений. Условия: цель новее установленной; аппарат в покое
  (`standby`/`outOfService`), нет обновления и обслуживания; релиз не заблокирован
  автооткатом; прошло 6 часов после отказа на этот релиз; проходят лимиты
  `update_app` (пауза 10 минут, 3 запуска и 12 неудач в сутки, счётчики общие с
  командой). Тестовая сборка (`SKIP_HEALTH_SIGNAL`) раскатку не получает.
* **Автооткат** релиза на аппарате блокирует его там до появления цели с
  БОЛЬШИМ `version_code`. Откат (`rollback_app`) раскатка не делает.
* **Автопауза.** Раскатка сама встаёт на паузу (`pause_reason`, запись в
  `rollout_log`): при одном автоматическом откате (`update_rolled_back`,
  `automatic=true`) или при двух ошибках установки на **разных** аппаратах кольца.
  Не считаются: busy, not_newer, rate_limited*, url_failed*, download_failed,
  no_space. Продолжить — только `rollout_set_status(..., 'active')`.
* **Права.** Организация берётся из самого объекта (раскатка, аппарат) и
  проверяется `is_org_member(org)`; чужое и несуществующее отвечают одним кодом
  `forbidden`. Только `rollout_create` берёт организацию пользователя:
  у него должна быть РОВНО одна строка в `org_members`, иначе ответ
  `no_org` / `ambiguous_org`. Время событий в автопаузе считается по
  `events.received_at` (серверное), не по `ts` аппарата.
* **Видимость.** Представление `rollout_progress` (аппарат, установленный и
  целевой код, `updated`/`waiting`, последний контакт); откаты и ошибки — из
  `events`; паузы и ручные действия — из `rollout_log`. В слепке настроек
  аппарата есть `rollout_target_code`.

## Чего НЕ делать

* Не создавать вторую активную раскатку в том же кольце: индекс и
  `rollout_set_status` откажут (`active_exists`). Сначала `done`/`cancelled`.
* Не менять `rollouts` напрямую: права на запись отозваны, только функции.
* Не раскатывать на `early`/`all` до проверок ниже.
* Не заливать в бакет тестовую сборку (`...-TEST-...apk`).

## Перед кольцом `early` и `all`

1. Серийный планшет (Syoung SY156-A510) проверен: root (`su`), выход скрипта из
   cgroup приложения (в протоколе `survive_ok`, а не `no_survive`), `pm install -r`
   и откат `-d`, ABI arm64-v8a.
2. Токены устройств перевыпущены (токен тестового планшета попадал в переписку).
3. Проведён `rls_rollouts.sql` на копии базы (участник организации и не
   участник; anon ничего не вызывает), результаты просмотрены.
4. Пройдена раскатка на кольцо `test` целиком: обновление в окне, откат по
   таймеру, автопауза.
5. Панель проверена на формат `devices.app_version` (`<версия>+<код>`).
