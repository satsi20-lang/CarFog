# Настройки при обновлении и очистке данных

Коротко: что хранится, что переживает обновление приложения и что теряется при
очистке данных или переустановке. Живая проверка на планшете не делалась; поведение
следует из того, где лежат данные, и покрыто тестами на загрузку старых настроек
(`test/device_spec_test.dart`, фикстуры `test/fixtures/app_config_1_7_0.json` и
`app_config_1_8_0.json`).

## Что и где хранится

| Что | Где | Ключ / файл |
|---|---|---|
| Основные настройки: цена, длительность, PIN, продувки, **названия ароматов по языкам**, флаги оборудования («установлено»), киоск, терминал, тариф, облако (номер, адрес, ключ, токен, включено), **порт шины**, **спецификация** (число насосов, языки) | SharedPreferences приложения (`/data/data/ee.carfog.dryfog/shared_prefs`) | `app_config` (один JSON) |
| Номер последней применённой заводской конфигурации | там же, отдельным ключом (заводской сброс его не стирает) | `factory_config_applied_id` |
| Очередь и история событий облака, история удалённых команд, журнал ошибок | там же | `cloud_event_queue`, `cloud_event_history`, `remote_command_history`, `remote_seen_command_ids`, `error_log` |
| Блокировка PIN, мастер-код (соль и хэш), лимиты обновлений и откатов, контрольная точка счётчика | там же и нативное хранилище приложения | разные ключи |
| Состояние «вывод из обслуживания» | нативное хранилище приложения | `OutOfServiceStore` |
| Заводской файл облачной связи | общий каталог **вне** приложения | `/sdcard/CarFog/device_config.json` |

## Обновление приложения (`adb install -r`, `pm install -r -d`, `update_app`)

Данные приложения **сохраняются** целиком: Android не трогает `shared_prefs` при
обновлении с тем же ключом подписи. Сохраняются:

* названия ароматов по языкам;
* цена и длительность обработки, продувки;
* PIN и мастер-код;
* флаги «установлено» (термопара, счётчик, монетоприёмник, модуль ввода-вывода);
* облачные настройки (номер, адрес, ключ, токен, «облако включено»);
* порт шины;
* спецификация (число насосов, языки);
* очередь событий, лимиты, блокировки.

Новая версия, у которой появились новые поля (например `busPort`, `spec*`), читает
старый JSON и подставляет для недостающих полей значения по умолчанию, остальное
не меняет. Неверное сохранённое значение порта или спецификации заменяется
значением по умолчанию (порт: `/dev/ttyS4`; spec: 4 насоса, `et,en,ru`).

**Заводской файл и обновление названия ароматов не перезаписывают никогда.**
Заводская запись меняет только облачные поля и (если в файле есть `spec`) поля
спецификации.

## Смена числа насосов (spec)

Число насосов (4…8) хранится в настройках (`specPumps`) и приходит заводским
файлом. Названия ароматов всегда хранятся для **всех 8** каналов по каждому языку:
* старые настройки с меньшим числом названий при загрузке дополняются нейтральными
  «Аромат 5…8» / «Flavor 5…8» / «Aroma 5…8»; существующие названия и порядок не
  меняются;
* при уменьшении числа насосов (например 6 → 4) названия лишних **остаются** в
  хранилище и возвращаются при увеличении;
* если число насосов уменьшили, пока выбран/оплачен аромат с убранным каналом,
  сессия отменяется (выходы гасятся, событие в журнал и облако).

## Очистка данных (`pm clear`) и переустановка (`adb uninstall` + установка)

Теряется всё, что лежит в приватных данных приложения: названия ароматов, цена,
длительность, PIN и мастер-код, флаги оборудования, порт шины, спецификация,
очередь событий, лимиты, состояние «вывод из обслуживания». Приложение
стартует с настройками по умолчанию.

Что и чем восстанавливается:

* **облачная связь** (номер, адрес, ключ, токен, «облако включено») и
  **спецификация** (число насосов, языки) возвращаются **заводским файлом**
  `/sdcard/CarFog/device_config.json`, пока он лежит на планшете (он переживает
  `pm clear` и переустановку; при `adb uninstall` придётся заново выдать
  `MANAGE_EXTERNAL_STORAGE`, `provision_push.sh` это делает). Поэтому до конца
  пуско-наладки файл остаётся, а после — удаляется (см.
  [docs/technician_guide.md](technician_guide.md));
* **остальное пока не восстанавливается**: названия ароматов, цену, PIN, флаги
  оборудования, порт шины придётся ввести заново в сервисном меню. Резервная копия
  настроек в облаке — отдельная задача (в этой части не делается).

## Как проверено

* Тесты загружают сохранённые настройки версий 1.7.0 и 1.8.0 (фикстуры) и
  проверяют, что названия ароматов, цена, PIN, облако, флаги и порт на месте, а
  spec получает значения по умолчанию.
* Тест сохранение–загрузка с пользовательскими названиями по языкам и spec.
* Тест заводского файла со `spec`: меняются только облако и spec.
* **Не проверено на живом планшете:** обновление `adb install -r` с 1.8.0 на 1.9.0
  и сохранение данных на реальном устройстве.
