# Аппаратный профиль: Syoung SY156-A510

Единственный источник констант профиля: `lib/models/hardware_profile.dart`
(id `sy156-a510`). Версии с 1.8.0 собираются только под этот планшет.

## Планшет

| Параметр | Значение |
|---|---|
| Модель | Syoung SY156-A510, 15,6" |
| Чип | RK3562 (arm64-v8a; также armeabi-v7a, armeabi), `ro.product.device` = `rk3562_t` |
| ОС | Android 13 (SDK 33), userdebug |
| Экран | 1080x1920 физически, плотность 240 → 720x1280 dp, **портрет**, поворот зафиксирован |
| Навигация | панель навигации есть; приложение работает в immersive |
| SELinux | **Permissive** (на CARFOG-001 был Enforcing) |
| Root | `su 0 sh -c "…"` (форма `su 0 …`; флаг `-c` у этого `su` не поддерживается, как и в приложении) |

Приложение рисуется в портрете: ориентация ограничена `portraitUp` /
`portraitDown`, размеры шрифтов и кнопок — в `lib/widgets/portrait_ui.dart`
(заголовки не мельче 36 sp, основной текст не мельче 22 sp, кнопки не ниже
72 dp, переключатель языка не ниже 64 dp).

## Последовательные порты (замер 08.10.2026, только чтение)

Существуют: `ttyS0`–`ttyS4`, `ttyS7`, `ttyS9`; `ttyS10`–`ttyS13` — ссылки на
`ttyP*`. `ttyS5` **на этом планшете нет**.

| Узел | Назначение |
|---|---|
| `/dev/ttyS4` (UART4, `ff6a0000`, разъём J25) | **порт шины RS485 по умолчанию**: выведен на DB9 с надписью «ttys4/RS485» (см. ниже) |
| белый 4-пиновый разъём **J11** = `/dev/ttyS3` (UART3) | UART 3,3 В (TTL), **RS485 там нет**; приложением не используется, ни к чему не подключён |
| `/dev/ttyS1` | занят Bluetooth-демоном — **запрещён** |
| `/dev/ttyUSB0`–`ttyUSB2` | USB-модем 4G (Quectel), RIL-демон держит `ttyUSB1` — **запрещены** |
| `/dev/ttyS9` | Bluetooth (rfkill) |
| `ttyS0` | ранняя консоль (earlycon), `ttyFIQ0` — консоль ядра |

### Разъёмы и уровни (данные производителя планшета, 09.10.2026)

| Разъём | Узел | Уровни | Контакты |
|---|---|---|---|
| белый 4-пиновый **J11** | `/dev/ttyS3` | TTL 3,3 В по умолчанию; RS-232 только при установке U35; RS485 нет | 1 GND, 2 RX, 3 TX, 4 VCC 3,3 В (опция 5 В) |
| **J25** | `/dev/ttyS4` | TTL по умолчанию; RS-232 при U9831; **RS-485 при U68** | 1 GND, 2 RX / A+, 3 TX / B-, 4 VCC |
| **DB9** (надпись «ttys4/RS485») | `/dev/ttyS4` | RS485 | 1 = B, 2 = A, 5 = GND |

Параметры шины: 9600, 8 бит, без чётности, 1 стоп-бит. Адреса: термопара 1,
счётчик Chint 3 (FC03 с 0x2000), модуль ввода-вывода CWT 5. Узлы `ttyS1`
(Bluetooth) и `ttyUSB0`–`ttyUSB2` (модем) не открываются никогда; `ttyS3` (J11,
TTL) не используется.

### Проба шины на ttyS4 через DB9 (10.10.2026, только чтение)

Проверялось из shell планшета (`su 0 sh -c`), приложение на время пробы
останавливалось (`am force-stop`). Порт: `stty 9600 cs8 -parenb -cstopb raw`.
Запросы только на чтение (FC01/02/03), ничего не записывалось. Кадры (CRC16
Modbus проверена эталонными векторами):

| Устройство | Кадр | Ответ (проба 10.10.2026) |
|---|---|---|
| термопара, адрес 1 | `01 03 00 00 00 01 84 0A` | `01 03 02 01 19 78 1E`: 0x0119 = 281 → **28,1 °C**, CRC верна |
| счётчик Chint, адрес 3 | `03 03 20 00 00 02 CE 29` | `03 03 04 43 68 99 9A A7 90`: float 0x4368999A = **232,6 В**, CRC верна |
| модуль, адрес 5 (входы) | `05 02 00 00 00 10 78 42` | `05 02 02 01 00 49 E8`: DI0 = 1, остальные 0, CRC верна |
| модуль, адрес 5 (выходы) | `05 01 00 00 00 0C 3D 8B` | `05 01 02 00 00 48 3C`: все выходы выключены, CRC верна |

**Все три устройства отвечают на ttyS4 через DB9 на 9600 8N1.** Стабильность:
20 запросов подряд термопаре (адрес 1): 20 из 20 ответов с верным CRC, 0 без
ответа, 0 ошибок CRC, температура 28,1…28,2 °C. Время отправки кадра
командами shell ≈65–90 мс (с накладными расходами `printf`/`date`); время самого
ответа в shell не измерялось.

**Рабочая схема на DB9** (сообщил владелец): контакт 1 = B, контакт 2 = A (по
наклейке), контакт 5 = GND подключён к GND шины (блок питания один, нуль общий).

История попыток (по словам владельца):

1. A на контакт 2, B на контакт 1 (по данным производителя), без GND: тишина.
2. A и B поменяны (A на 1, B на 2), без GND: тишина.
3. A на 1, B на 2, GND на контакт 5: тишина.
4. A на 2, B на 1, GND на контакт 5: тишина (14:56).
5. В 15:26 устройства ответили на все запросы. **Причина тишины в попытках 1–4:
   плохой контакт в разъёме DB9: штырь утапливался, и связи не было.** Владелец
   нашёл и исправил контакт; схему A/B, питание и GND между попытками 4 и 5 он не
   менял. Значит, результаты попыток 1–4 (в том числе вывод «перестановка A/B и
   GND ничего не дают») **недостоверны** и ни о полярности, ни о GND ничего не
   говорят. Работает схема из начала раздела (1 = B, 2 = A, 5 = GND). Нужен ли GND
   на самом деле и допустима ли перестановка A/B, отдельно не проверялось (по
   схеме без GND работа не измерялась).

Заметки по поведению:

* Эхо своих байт не возвращается (приёмник отключается на передаче).
* Направление RS485 в ядре не настроено (в device-tree нет `rs485-rts-active`,
  `linux,rs485-enabled-at-boot-time`; драйвер `dw-apb-uart`), но чтение и
  ответы работают без `TIOCSRS485`: трансивер, судя по всему, переключает
  направление сам.
* Приложение само опрашивает ttyS4 при старте; при пробе из shell его нужно
  останавливать: два ведущих на одной шине перемешивают кадры (в первой
  успешной пробе в буфер попал трафик самого приложения, в том числе ответ на
  запись выходов `05 0F …`). Чистая проба — с остановленным приложением.

### Порт шины — настройка

`AppConfig.busPort` (по умолчанию `/dev/ttyS4`). Хранится как остальные
настройки; в слепок настроек/диагностики попадает `bus_port` (не секрет) и
`hardware_profile`.

- **Допустимы** только `/dev/ttyS<число>`, `/dev/ttyUSB<число>`,
  `/dev/ttyACM<число>`; всё остальное отклоняется.
- **Запрещены всегда** (даже выбранные вручную): `/dev/ttyS1`, `/dev/ttyUSB0`,
  `/dev/ttyUSB1`, `/dev/ttyUSB2` (`BusPortPolicy` в `lib/models/bus_map.dart`,
  зеркало — `BusPortPolicy.kt`). Сохранённое запрещённое значение при чтении
  заменяется значением по умолчанию. Проверка стоит ещё и в `ModbusService`
  (до вызова канала) и в Kotlin (`requirePort`: без аргумента `port` —
  ошибка `NO_PORT`, запасного порта нет).
- **Смена**: сервисное меню → «Диагностика» → «Порт шины RS485». Список —
  найденные узлы; запрещённые показаны с пометкой и не выбираются
  (предупреждение). Нужен сервисный PIN; смена пишется в журнал и в облако
  (`config_changed`, `bus_port_changed`). Вступает в силу **после перезапуска
  приложения**. Менять только по указанию техподдержки.
- Заводская запись (`device_config.json`), удалённые команды
  (`update_config`, `factory_reset` и др.) этот параметр не трогают;
  заводской сброс по команде его сохраняет.

## Запись заводской конфигурации на этом планшете

`MANAGE_EXTERNAL_STORAGE` на этой прошивке возвращает системный демон
**autohook** (`/system/bin/autohook`): при запуске приложения режим на уровне
uid снова `allow`, даже после `appops reset`. Поэтому запасной путь через
`su` (при отсутствии права) здесь не проверялся. См. docs/provisioning.md.

## Что проверено и что нет

Проверено на живом планшете (08.10.2026): установка 1.7.0+21, запись
конфигурации, автоприменение после `pm clear`, `pm install -r -d` через
`su 0 sh -c`, чтение `getprop` через `su`, скриншоты экранов в портрете.

Проверено на живом планшете (10.10.2026):
* шина на `ttyS4` через DB9: термопара (адрес 1), счётчик (адрес 3) и модуль
  ввода-вывода (адрес 5) отвечают, 20 запросов подряд термопаре — 20 из 20 с
  верной CRC;
* приложение само читает шину и показывает на вкладке «Датчики» температуру
  ≈28 °C и напряжение ≈230 В;
* экраны клиента в портрете осмотрены владельцем и в норме.

НЕ проверено: длительная работа на шине; запись выходов под нагрузкой (ТЭН,
насосы); оплата и обработка на этом планшете; работа шины без GND и без
перестановки полярности A/B (рабочая схема 1 = B, 2 = A, 5 = GND подтверждена
только в таком виде); режим SELinux Enforcing; перезагрузка; `adb uninstall`;
запасной путь через `su` без права `MANAGE_EXTERNAL_STORAGE`.
