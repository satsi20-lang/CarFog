# Переводы клиентских экранов (с 1.10.0)

Тексты экранов клиента лежат не в коде, а в файлах `assets/i18n/` и входят в
APK. Набор языков конкретного аппарата задаёт спецификация (`spec.langs`, порядок
= порядок на экране выбора языка, `spec.default_lang` — язык по умолчанию; см.
[docs/provisioning.md](provisioning.md)). Показывается только то, что есть в spec
**и** выпущено (`released`) здесь.

## Файлы

```
assets/i18n/manifest.json   список языков: родное название, статус, версия
assets/i18n/en.json         эталонный набор ключей (обязателен)
assets/i18n/et.json
assets/i18n/ru.json
assets/i18n/<код>.json      остальные языки — по мере перевода (волны 3b)
```

`<код>.json` — плоский словарь «ключ → строка» в UTF-8. Ключ начинается с имени
экрана: `standby.*`, `language_select.*`, `select_flavor.*`, `payment.*`,
`preparing.*`, `treating.*`, `finished.*`, `error.*`, `out_of_service.*`.

```json
{
  "payment.title": "ОПЛАТА",
  "preparing.hint4": "4. После завершения обработки насос ещё {seconds} сек будет распылять — не трогайте шланг",
  "finished.countdown": "{seconds}с"
}
```

Параметры в фигурных скобках подставляет приложение: `{seconds}` (секунды),
`{temp}` (градусы), `{flavor}` (название аромата). В переводе должен быть **тот
же набор** параметров, что в `en.json` (порядок любой); единицы («с», «sek», «s»,
«°C») — часть перевода.

`manifest.json`:

```json
{
  "languages": {
    "de": { "name": "Deutsch", "status": "draft", "version": 0 },
    "en": { "name": "English", "status": "released", "version": 1 }
  }
}
```

* `name` — родное название, им подписана кнопка языка (Eesti, Ελληνικά, Українська…);
* `status` — `released` (показывается клиентам) или `draft` (не показывается);
* `version` — номер редакции перевода (увеличивать при каждой правке
  выпущенного языка).

В manifest уже есть строки всех 27 кодов каталога; выпущены et, en, ru. У lv,
lt, fi, sv, pl, de, fr есть черновые файлы (волна 1, `draft`, version 1, см.
ниже); у остальных статус `draft` и пока **нет файла** (язык без файла не
показывается вообще, даже при включённом показе черновиков).

## Правила показа

* Показываемые языки = `spec.langs` ∩ (`released` и файл загружен), в порядке
  spec. Пусто → `en`. Язык по умолчанию — `spec.default_lang`, если он
  показывается, иначе первый показываемый.
* Один язык — экрана выбора языка нет, переключателя на экранах нет.
* 2–6 языков — экран выбора: один столбец крупных кнопок; 7–24 — сетка в 2
  столбца (с прокруткой). Заголовок экрана — `language_select.title` на каждом
  показываемом языке (одинаковые строки показываются один раз); делайте его
  коротким («VALI KEEL», «SELECT LANGUAGE»).
* Переключатель на экранах: до 3 языков — кнопки с кодами (ET/EN/RU), больше —
  кнопка с кодом текущего языка, по нажатию окно со всеми языками. Смена языка
  не прерывает оплату и обработку.
* После конца сессии (завершение, отмена, таймаут оплаты, возврат с экрана
  ошибки) и после 30 с простоя на заставке язык возвращается к языку по
  умолчанию. Выбранный язык между перезапусками не хранится: после запуска —
  экран выбора языка (или сразу заставка, если язык один).

## Запасная цепочка

Строка ищется **строго**: запрошенный язык → `en` → сам ключ. Пустая строка
считается отсутствующей. Ни отсутствующий ключ, ни отсутствующий или
повреждённый файл не дают исключения: экран всегда что-то показывает, ошибка
пишется в журнал (`[I18n]`). Отсутствие ключа даже в `en` — ошибка разработки:
тесты (`test/i18n_test.dart`, `test/i18n_screens_test.dart`) на неё падают.

Названия ароматов вносит техник во вкладке «Ароматы» на ru/en/et. Для другого
языка название берётся по цепочке: язык → en → ru → любое непустое →
`Flavor N`.

## Что не переводится

* Сервисное меню, экран PIN и секция порта шины (экраны техника) остаются на
  ru/en/et таблицами в коде. Если у клиента выбран другой язык, они
  показываются на `en`.
* «CaRFog OÜ» (название компании), суммы («2.00 €»), таймер «1:57»,
  температура «190°C».

## Как добавить язык

1. Скопируйте `en.json` в `<код>.json` и переведите **все** строки (ключи не
   менять, параметры `{…}` сохранить). Код — из каталога spec (нижний регистр).
2. В `manifest.json` у языка оставьте `"status": "draft"`, `"version": 1`.
3. `flutter test test/i18n_test.dart` — проверка: набор ключей совпадает с en,
   параметры те же, у released нет пустых строк; макет с длинными строками.
4. Соберите APK, установите на проверочный аппарат с этим языком в spec.
5. Носитель языка проверяет текст **на аппарате**: сервисное меню → вкладка
   «Диагностика» → тумблер **«Показывать черновые переводы»** (после PIN; по
   умолчанию выключен, не сохраняется — после перезапуска снова выключен;
   включение пишется в журнал и событием `debug_mode_changed` в облако). Выйти
   из меню, выбрать язык переключателем, пройти экраны (в том числе ошибку и
   «не работает» — их можно вызвать отладочными тумблерами той же вкладки).
6. Только после письменного подтверждения носителя: `"status": "released"`,
   новая сборка.

**Обязательно:** фразы про оплату, возврат денег, аварию и опасность — ключи
`payment.*`, `error.*`, `out_of_service.*` (а также `treating.cancel_body` про
невозврат оплаты) — проверяет носитель языка **до** перевода в `released`.
Ошибка в них — это неверное обещание клиенту о деньгах или о безопасности.

## Порядок выпуска языка (лист → носитель → правки → released)

1. **Лист:** `python3 tool/i18n_review.py <код>` (или `--all` для всех draft с
   файлом) создаёт `docs/i18n_review/<код>.md`: шапка, пометки переводчика,
   таблица «ключ | en | перевод | замена» (сначала критичные: `payment.*`,
   `error.*`, `out_of_service.*`, `treating.cancel_*`, `preparing.hint*`,
   `finished.*`), чек-лист.
2. **Носитель** заполняет столбец «замена» и чек-лист, подписывает.
3. **Правки** переносятся в `assets/i18n/<код>.json`; `flutter test`
   (`test/i18n_wave1_test.dart`, `test/i18n_test.dart`).
4. **`version` +1** в manifest (номер проверенной редакции).
5. Только после этого `"status": "released"` и новая сборка.

### Волна 1 (lv, lt, fi, sv, pl, de, fr) — черновики

Файлы есть, статус **draft**, version 1: это **машинный перевод, не
проверенный носителем**. На боевых аппаратах эти языки не показываются (только
при включённом тумблере «Показывать черновые переводы»). Листы для носителей:
`docs/i18n_review/<код>.md`.

## Чеклист / письмо носителю языка

> Здравствуйте! Просим проверить перевод интерфейса аппарата сухого тумана
> CaRFog на язык: **<язык>**. Аппарат стоит на автомойке; клиент выбирает
> аромат, платит монетами или картой, аппарат 40 с распыляет аромат в салоне.
> Важно, чтобы тексты были короткими, понятными с 1 метра и **точными в
> вопросах оплаты и возврата денег**.
>
> Прилагаем файл `<код>.json` и английский оригинал `en.json`. Если можете —
> посмотрите и на самом аппарате (покажет техник).
>
> Особенно внимательно (обязательная проверка):
>
> * Оплата: `payment.title`, `payment.flavor`, `payment.price`, `payment.paid`,
>   `payment.remaining`, `payment.instruction`, `payment.instruction_with_card`,
>   `payment.instruction_coin_down_with_card`, `payment.cancel`;
> * Отмена обработки (оплата не возвращается): `treating.cancel_title`,
>   `treating.cancel_body`, `treating.cancel_yes`, `treating.cancel_no`;
> * Ошибки и возврат денег: `error.overheat.*`, `error.timeout.*`,
>   `error.sensor.*`, `error.generic.*`, `error.bus_unavailable.*`,
>   `error.coin_acceptor_unavailable.*`, `error.heater_failure.*`,
>   `error.heater_sensor_fault.*`, `error.contact`, `error.returning`,
>   `error.countdown`;
> * Аппарат не работает: `out_of_service.title`, `out_of_service.detail`.
>
> Отметьте для каждой строки: ✓ верно / ✗ исправить (ваш вариант). Не меняйте
> слова в фигурных скобках `{seconds}`, `{temp}`, `{flavor}` — их подставляет
> аппарат. Напишите, пожалуйста, в конце: «Перевод на <язык> проверен,
> замечаний нет / замечания выше», имя и дату.

Ответ носителя хранится вместе с заявкой на выпуск языка; номер `version` в
manifest — тот, что проверен.

## Известные места для проверки носителем (et/en/ru перенесены без правок)

Тексты et/en/ru перенесены из кода **без изменения формулировок** (сверка с
эталоном `test/fixtures/i18n_baseline.json`). При проверке стоит обратить
внимание:

* `error.overheat.detail` содержит число 240°C (совпадает с порогом
  `HeaterThresholds.overheatAbortC`; при смене порога текст нужно править во
  всех языках); `error.timeout.*` и `error.sensor.*` (225°C, 600 секунд) сейчас
  клиенту не показываются — таймаут прогрева и отказ датчика уходят в
  `heater_failure` / `heater_sensor_fault`.

## Шрифт

Своего шрифта приложение не подключает: на Android используется системный
Roboto. Проверено по таблице символов Roboto Regular и Bold (та же гарнитура в
Flutter SDK): есть латиница с диакритикой (Ä Ö Ü Õ Š Ž Ł Ą Ę Ő Ű ț ș ă î и др.),
греческий с ударениями (ά έ ή ί ό ύ ώ), кириллица (в том числе болгарская и украинская Є І Ї Ґ),
мальтийские Ċ Ġ Ħ Ż, ирландские á é í ó ú, знаки € ° · — « » „ “. Системные
шрифты самого планшета не проверялись (нет доступа к планшету).
