# Сводка цикла в `session_complete` (с 1.10.1)

В данные события `session_complete` (и при успехе, и при прерывании — это одно
и то же событие с `completed: false`) добавлены компактные поля о самом цикле:
температура термопары, прогрев, ТЭН, длительности фаз. Те же числа одной
строкой пишутся в журнал приложения:

```
[Cycle] cycle_summary session=1791641138258 completed=true preheat_s=90.0 start_temp_c=21.0 preheat_end_temp_c=190.8 peak_temp_c=201.0 final_temp_c=188.0 heater_switches=4 heater_on_s=120.2 phase_preheat_s=91.2 phase_compressor_startup_s=5.0 phase_treating_s=40.0 phase_purge_s=5.0
```

Это **только запись**: логика ТЭНа, защит, оплаты и обработки не менялась,
дополнительных опросов шины нет — используются показания термопары, которые
экраны прогрева и обработки и так читают (раз в 3 с), и уже существующие
команды на ТЭН. Сборщик — `lib/services/cycle_summary_service.dart`.

## Поля

Температуры — °C, округлены до 0,1; длительности — секунды, до 0,1.
Поле **отсутствует**, если значения нет (не ноль).

| Поле | Что значит |
|---|---|
| `preheat_s` | Прогрев: от команды на включение ТЭНа до достижения цели (190°C). Только если цель достигнута. Раньше это поле приходило от счётчика (только с установленным счётчиком); определение то же. |
| `start_temp_c` | Первое годное показание термопары в цикле (до команды на ТЭН). |
| `preheat_end_temp_c` | Температура в момент достижения цели прогрева. |
| `peak_temp_c` | Максимум за цикл (прогрев и обработка). |
| `final_temp_c` | Последнее годное показание до конца сессии. |
| `heater_switches` | Сколько раз реле ТЭНа сменило состояние за цикл: включение в прогреве, переключения термостата в обработке, выключение. Повторная команда «вкл» при уже включённом ТЭНе не считается. |
| `heater_on_s` | Суммарное время, когда ТЭН был включён (от команды «вкл» до выключения катушки). |
| `phase_preheat_s` | Экран прогрева: от входа до цели или до отказа/отмены. |
| `phase_compressor_startup_s` | Запуск компрессора (до включения насоса). |
| `phase_treating_s` | Обработка (насос аромата включён). |
| `phase_purge_s` | Продувка после обработки (ТЭН и насос выключены). |
| `preheat_aborted` | `true`, если прогрев не завершился. |
| `preheat_abort_reason` | Причина — тот же код, что в журнале ошибок экрана прогрева: `HEAT_TIMEOUT`, `HEAT_OVERHEAT`, `HEAT_NO_POWER`, `HEAT_NO_THERMOCOUPLE`, `HEAT_SENSOR_FAULT_<ПОДТИП>`, `HEAT_USER_CANCEL`; `preheat_abandoned` — экран закрыт извне (удалённый сброс). |
| `temp_curve_c` | Облегчённая кривая: не чаще одной точки в 10 с, не больше 40 точек (при переполнении каждая вторая точка выбрасывается, шаг удваивается). Есть, только если точек ≥ 2. |
| `temp_curve_step_s` | Шаг кривой, с (10, 20, 40…). |

Фазы есть только те, что прошли: при отказе в прогреве будет только
`phase_preheat_s`. Если термопара не дала ни одного годного показания (или не
установлена) — температурных полей и кривой нет; если ТЭН не включался — нет
`heater_switches` / `heater_on_s`. Событие уходит в любом случае.

## Размер

Обычный цикл (прогрев ~90 с) — около 500 символов JSON вместе с прежними полями;
часовой цикл — около 450 (кривая прорежена до ~22 точек). Предел данных события
— `CycleSummaryLimits.maxEventDataChars` = 4096 символов (в
`lib/models/remote_limits.dart`; ни приложение, ни база отдельного предела не
задают, число не измерено). Если событие вместе с кривой больше предела
(например, большие подробности отказа), кривая выбрасывается, сводные числа
остаются, в журнал — одна строка.

## Надёжность

Любая ошибка сборщика проглатывается: цикл продолжается, `session_complete`
уходит без новых полей, в журнале строка `cycle_summary: ошибка сбора`.
Старые события и панель без новых полей работают как раньше (поля только
добавлены).

## Не проверено

На живом аппарате не проверялось: сводка покрыта тестами с подставными
временем и температурами (`test/cycle_summary_test.dart`).
