# Стенд терминала Nayax по MDB (с 1.10.9+44, формат с железа — 1.10.11+47)

## Что это

Вкладка сервисного меню **«Терминал (стенд)»** нужна для проверки терминала
**Nayax VPOS Media 4**. Терминал подключается по шине MDB через адаптер
**Wafer MDB-RS232** с выходом USB. Адаптер вставляется в USB-порт планшета.

* Стенд **не связан с боевой оплатой**. Экран оплаты, монетоприёмник,
  импульсный терминал (DI) и тумблер «Терминал» в настройках работают как
  раньше. Флага, который переключал бы боевую оплату на MDB, нет.
* **Тестовый режим: реальное списание.** Если терминал одобрит оплату,
  деньги спишутся с приложенной карты по-настоящему.
* Сам стенд отправляет только три вида команд:
  * команды по кнопкам;
  * шаги режима «одна тестовая оплата 0,10 €», который запускается кнопкой
    с подтверждением;
  * опрос setup раз в 60 с, пока приём включён и сессии нет.
* Шина Modbus (RS485, ttyS4) стендом не используется. У адаптера свой путь
  через USB-хост Android, свои потоки чтения и таймеров и свой канал
  `com.carfog.dryfog/mdb_bench`.
* При выходе из сервисного меню порт стенда закрывается. Команды при этом
  не отправляются.

Где лежит код:
* `MdbCashlessProtocol.kt`: команды и разбор кадров;
* `MdbFrameReader.kt`: чтение и деление на кадры;
* `MdbTestPayment.kt`: тестовая оплата;
* `MdbKeepAlive.kt`: опрос раз в 60 с;
* `MdbBenchLog.kt`: журнал;
* `MdbPortCloser.kt`: закрытие порта в фоне;
* `MdbUsbBench.kt`: USB, разрешение, канал;
* `lib/screens/service/mdb_bench_tab.dart`: экран.

Используется библиотека usb-serial-for-android 3.11.0 (MIT, JitPack).

## Формат адаптера Wafer (подтверждён на железе)

* Порт 9600 бод, 8 бит, без чётности, 1 стоп-бит. Адаптер — FTDI FT232R,
  VID `0403`, PID `6001`.
* Команды отправляются **байтами**.
* Адаптер отвечает **текстом ASCII**: hex-символы через пробел, кадр
  заканчивается `\r\n`. Например, `10 03 03 E8\r\n`.
* **Ответ на нашу команду идёт без префикса**:
  * `00` — ACK (команда принята);
  * `01 …` — ответ на setup.
* **События терминала идут с префиксом `10`** (адрес кассового устройства
  MDB).
* Адаптер сам опрашивает устройства MDB (POLL) и присылает события.
* Два кадра могут прийти подряд с паузой около 85 мс, например `00`, а
  затем `10 07`.
* Если терминал занят, адаптер может не ответить. Тогда команду повторяют
  позже.

### Деление на кадры

Кадр кончается на `\n`. Кадр закрывается сразу, даже если два кадра
пришли одним USB-пакетом. Кадр без `\r\n` закрывается паузой **60 мс** без
новых байтов. Паузу 85 мс между кадрами это не склеивает. Неполный кадр
после паузы попадает в журнал и разбирается как «не распознано». В журнале
указано время первого байта кадра и длительность приёма.

### Ответ на setup

`01 01 19 78 01 02 78 0D 1B` расшифровывается так:

| Байты | Значение |
|---|---|
| `01` | ответ на setup |
| `01` | уровень 1 |
| `19 78` | страна 1978 (EUR) |
| `01` | масштаб 1 |
| `02` | знаков после запятой: 2 |
| `78` | отклик 120 с |
| `0D` | опции 0x0D |
| `1B` | контрольная сумма: сумма первых 8 байт по модулю 256 |

Ответ без контрольной суммы, с неверной суммой или с масштабом 0 **не
принимается**. Масштаб из такого ответа не используется.

Цена в единицах терминала равна `сумма / (масштаб × 10^-знаков)`. При
масштабе 1 и 2 знаках 0,10 € = 10 единиц = `00 0A`.

### События терминала

| Кадр | Смысл |
|---|---|
| `10 03 03 E8` | начало сессии, доступно 1000 единиц (карта приложена) |
| `10 04` | терминал просит отменить сессию (нужно ответить `13 04`) |
| `10 05 00 0A` | оплата одобрена на 10 единиц |
| `10 06` | отказ в оплате |
| `10 07` | конец сессии |
| `10 08` | отменено (стандарт MDB, на железе не встречалось) |

Всё, что не совпало с этим точно, помечается «не распознано» и не
используется. Сюда относятся события без префикса, другая длина, склеенные
кадры и мусор. Сырой вывод в журнале важнее разбора.

## Команды

| Кнопка | Байты | Смысл |
|---|---|---|
| setup | `11 00 01 00 00 00` | настройка: уровень 1, без дисплея |
| prices | `11 01 FF FF 00 00` | максимальная и минимальная цена |
| enable / disable | `14 01` / `14 00` | включить / выключить приём карт |
| rcancel | `14 02` | сброс читателя |
| Запрос оплаты | `13 00 ЦЕНА(2) ТОВАР(2)` | 0,10 € = `13 00 00 0A 00 01`, только после окна «Списать …?» |
| ok | `13 02 00 01` | успех выдачи (товар 1) |
| cancel | `13 01` | отмена vend |
| vendfail | `13 03` | ошибка выдачи: возврат после одобрения |
| done | `13 04` | конец сессии |
| id | `17 00` + 29 байт | ID автомата: `CRF`, `000000000001`, `DRYFOG`, `01 10`. Что ждёт Nayax, **не подтверждено** |
| raw | свои байты | ввод проверяется на чётную длину и символы 0-9 A-F |

Ручной «Запрос оплаты» берёт масштаб и число знаков из ответа на setup.
Пока ответа нет, запрос не отправляется. При закрытии порта ответ на setup
сбрасывается. Если сумма не делится на шаг терминала или выходит за
0..65535 единиц, на экран выводится ошибка с цифрами. Округления нет.

## Порядок команд для оплаты

```
setup  ->  01 01 19 78 01 02 78 0D 1B
prices ->  00
enable ->  00
          (приложить карту)  <- 10 03 03 E8
vend 13 00 00 0A 00 01   ->  10 05 00 0A   (одобрено 10 ед.)
13 02 00 01 (успех)      ->  00
13 04 (конец сессии)     ->  00, затем 10 07
disable 14 00            ->  00
```

* При отказе (`10 06`) отправляется `13 04`.
* Если одобрена другая сумма, отправляется `13 03` (возврат), затем `13 04`.

Паспорт подтверждает формат ACK (`00`) и пару «`00`, затем `10 07`» после
`13 04`. Что ACK приходит после **каждой** из prices, enable, `13 02` и
`14 00`, — **допущение, не подтверждено**. Режим тестовой оплаты ждёт ACK
после prices и enable. Если ACK не пришёл за 3 с, режим останавливается с
`14 00`, он не идёт дальше наугад.

### Урок с железа: после 10 04 нужно отправить 13 04

Если терминал прислал `10 04` (запрос отмены сессии), автомат обязан
ответить `13 04` (конец сессии). **Иначе терминал не читает новую карту**,
и стенд как будто «завис». В ручном режиме нажмите **done**. Режим тестовой
оплаты делает это сам.

## Режим «одна тестовая оплата 0,10 €»

Запускается кнопкой **«Тестовая оплата 0,10 €»** после окна «Будет
списано 0,10 € с карты». Без «Списать» ничего не отправляется.

1. `setup`. Ждём ответ до 5 с. По ответу 0,10 € должно равняться ровно 10
   единицам, иначе оплата не запускается.
2. `prices`, ждём ACK `00` до 3 с. Затем `enable`, снова ждём ACK `00` до
   3 с.
3. Ждём `10 03` до **60 с**. На `10 03` сразу (меньше 1 с) уходит **один**
   vend на 10 единиц.
   * Если в `10 03` нет суммы или она меньше 10 единиц, vend не
     отправляется, уходит `13 04`.
4. Ответ на vend:
   * `10 05` на 10 единиц: `13 02 00 01`, затем `13 04`, ждём `10 07` до
     10 с. Это **успех**.
   * `10 05` на другую сумму или без суммы: `13 03` (возврат), затем
     `13 04`, на экране ошибка.
   * `10 06` или `10 04`: `13 04`.
   * Нет ответа 60 с: `13 01` (отмена vend), затем `13 04`. Если после
     отмены всё же пришло одобрение, уходит `13 03`. В этом случае
     **проверьте списание в кабинете Nayax**.
5. В конце **любого** исхода уходит `14 00` (disable).

Ограничения режима:
* Сумма жёстко 10 единиц.
* Второй vend за запуск невозможен.
* Ручные команды, другие суммы, `id` и `raw` недоступны до конца режима.
* Кнопка **«Прервать»** срабатывает как истечение времени текущего шага: та
  же отмена и `14 00`.
* Если порт закрыт или адаптер выдернут посреди оплаты, `14 00` отправить
  нельзя. На экране будет итог «прервано», а если vend уже ушёл,
  предупреждение проверить кабинет Nayax.

## Опрос раз в 60 с

Пока приём включён (`14 01` отправлено, `14 00` ещё нет) и сессии нет (вне
`10 03`…`10 07`), стенд раз в 60 с шлёт `setup` и ждёт ответ 5 с.

* Если ответа нет, в журнал пишется «адаптер молчит», а на экране
  появляются кнопки setup, prices и enable.
* **Сам стенд их не повторяет.**
* Во время тестовой оплаты опрос не идёт: у неё свои ожидания.

## Порядок проверки на планшете

1. **Питание адаптера Wafer строго 24 В.** Подключить терминал к адаптеру,
   адаптер к USB-порту планшета.
2. Сервисное меню (PIN) → «Терминал (стенд)» → **«Найти USB-устройства»**.
   В списке должны быть VID 0403, PID 6001 и драйвер FtdiSerialDriver.
3. **«Открыть порт»**. Если разрешения на USB ещё нет, Android покажет
   стандартное окно разрешения (см. ниже). После согласия порт откроется
   сам.
4. **«Тестовая оплата 0,10 €»** → «Списать» → приложить карту, когда
   состояние сменится на «приложите карту». Либо пройти по шагам вручную
   по таблице «Порядок команд».
5. **«Закрыть порт»**. Забрать журнал (см. ниже).

## Журнал

* В журнал попадают все кадры, отправленные (`->`) и принятые (`<-`), и
  служебные строки (`**`).
* Строка содержит время с миллисекундами, `hex`, `ascii`, сырые байты и
  разбор. Для принятых кадров добавляется время первого байта и
  длительность.
* В памяти хранятся последние 2000 строк. Кнопка «Очистить» чистит только
  экран. **«Копировать журнал»** кладёт журнал в буфер обмена.
* Те же строки дописываются в файл
  `/sdcard/Android/data/ee.carfog.dryfog/files/mdb_bench.log`. При 5 МБ он
  переименовывается в `mdb_bench.log.1`.
* В облако журнал **не уходит**.
* Как забрать файл: владелец открывает окно сетевого ADB («Облако» →
  «Сетевой ADB на 30 минут»), затем
  `adb pull /sdcard/Android/data/ee.carfog.dryfog/files/mdb_bench.log`.

## Разрешение на USB

* Разрешение запрашивается стандартным окном Android через
  `UsbManager.requestPermission` и PendingIntent с `FLAG_MUTABLE` и явным
  пакетом.
* В журнал пишется результат запроса (выдано или нет), VID, PID и имя
  устройства.
* Обходов нет: разрешение не выдаётся программно, API Device Owner для USB
  не используется.
* В манифесте есть фильтр устройств для адаптера (`MdbUsbAttachAlias`,
  `res/xml/mdb_usb_device_filter.xml`, FTDI 0403:6001). Тот же VID/PID есть
  в таблице FtdiSerialDriver библиотеки. При подключении адаптера Android
  может предложить «открыть CaRFog для этого устройства». Согласие с
  отметкой «по умолчанию» даёт постоянное разрешение на это устройство.
* Как оба окна ведут себя под Lock Task + Device Owner, **не проверено**.
  Если окна нет, запасной путь такой: «Киоск» → временный выход из
  блокировки, затем «Открыть порт» и согласие в окне.

## Чего не делать

* **Никогда не вскрывать корпус терминала Nayax.** При срабатывании датчика
  вскрытия терминал блокируется навсегда.
* **Питание адаптера Wafer — строго 24 В.**
* **Не менять настройку Syoung «OTG HOST»** (хост или устройство) на
  CARFOG-100: она может отключить USB-хост.
* Не гонять лишние оплаты: каждое одобрение списывает деньги.
* Не оставлять терминал включённым (`enable`) без присмотра.

## Проверка зависимостей Gradle (с 1.10.9+45)

Файл `android/gradle/verification-metadata.xml` хранит sha256 всех
артефактов сборки Android, включая usb-serial-for-android 3.11.0 с JitPack:

* `usb-serial-for-android-3.11.0.aar`:
  `f74032134a4ded3276ccc02bec0d278015bc3c93ef04473b98fbda2771d7e439`
* `usb-serial-for-android-3.11.0.module`:
  `388b212a7e75b46ef6f409a5b715ed76522c9a4e30d0e21b39b4da00afdb2280`

Если артефакт не совпадает с записью, сборка падает с ошибкой «Dependency
verification failed». Проверка включается сразу для всех зависимостей, по
одной её включить нельзя. Поэтому после обновления Flutter, AGP, Kotlin или
любой библиотеки файл нужно пересоздать (из папки `android/`, с JAVA_HOME
Android Studio):

```
./gradlew --write-verification-metadata sha256 :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest
```

Затем посмотрите `git diff` файла: новые хеши должны относиться только к тем
библиотекам, которые вы меняли.
