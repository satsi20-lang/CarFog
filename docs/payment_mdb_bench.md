# Стенд терминала Nayax по MDB (с 1.10.9+44)

## Что это

Вкладка сервисного меню **«Терминал (стенд)»** нужна для ручной проверки
терминала **Nayax VPOS Media 4**. Терминал подключается по шине MDB через
адаптер **Wafer MDB-RS232**, у которого выход USB. Адаптер вставляется в
USB-порт планшета.

* Стенд **не связан с боевой оплатой**. Экран оплаты, монетоприёмник,
  импульсный терминал (DI) и тумблер «Терминал» в настройках работают как
  раньше. Флага, который переключал бы боевую оплату на MDB, пока нет.
* Стенд ничего не отправляет сам: каждая команда уходит только по кнопке.
* **Тестовый режим: реальное списание.** Если терминал одобрит запрос
  оплаты (vend), деньги спишутся с приложенной карты по-настоящему,
  например 0,10 €.
* Шина Modbus (RS485, ttyS4) стендом не используется. У адаптера свой путь
  через USB-хост Android, свой поток чтения и свой канал
  `com.carfog.dryfog/mdb_bench`.
* При выходе из сервисного меню порт стенда закрывается. Команды при
  этом не отправляются.

Код находится здесь: `MdbCashlessProtocol.kt` (команды и разбор, чистый
Kotlin), `MdbFrameReader.kt` (чтение с разделением сообщений по паузе),
`MdbBenchLog.kt` (журнал), `MdbUsbBench.kt` (USB, разрешения, канал),
`lib/screens/service/mdb_bench_tab.dart` (экран). Используется библиотека
usb-serial-for-android 3.11.0 (MIT, JitPack).

## Параметры адаптера (из инструкции Wafer)

* 9600 бод, 8 бит, без чётности, 1 стоп-бит.
* Команды отправляются **байтами**. Ответы и события адаптер присылает
  **текстом** из hex-символов, например `010109720102070D94`.
* Адаптер сам опрашивает устройства MDB (POLL) и присылает события.
* Если терминал занят, адаптер может не ответить. Тогда команду
  повторяют позже. Ответ в реальном времени не гарантирован.

## Команды на экране

| Кнопка | Байты | Смысл |
|---|---|---|
| setup | `11 00 01 00 00 00` | настройка: уровень 1, без дисплея |
| prices | `11 01 FF FF 00 00` | максимальная и минимальная цена |
| enable / disable | `14 01` / `14 00` | включить / выключить приём карт |
| rcancel | `14 02` | отмена сессии на стороне терминала |
| Запрос оплаты | `13 00 ЦЕНА(2) ТОВАР(2)` | 0,10 € при масштабе 1 и 2 знаках = `13 00 00 0A 00 01` |
| ok | `13 02 00 01` | товар выдан (товар 1) |
| cancel | `13 01` | отмена оплаты |
| done | `13 04` | конец сессии |
| id | `17 00` + 29 байт | ID автомата: `CRF`, серийный `000000000001`, модель `DRYFOG`, версия `01 10` |
| raw | свои байты | проверяется на чётную длину и символы 0-9 A-F |

Цена в единицах терминала считается так: `сумма / (масштаб × 10^-знаков)`.
Масштаб и число знаков берутся **из ответа на setup**. Пока ответа нет,
«Запрос оплаты» не отправляется и экран показывает предупреждение. При
закрытии порта (кнопкой, при отключении адаптера, при выходе из меню) ответ
на setup сбрасывается: после повторного открытия сначала снова setup. Если
сумма не делится на единицу терминала без остатка или выходит за 0..65535
единиц, это ошибка, округления нет.

Какие значения ID ждёт Nayax и нужна ли команда `id` вообще, **не
подтверждено**.

## Разбор ответов

* Ответ на setup: `01 уровень страна(2) масштаб знаки отклик опции
  [контрольная сумма]`. Пример из инструкции: `010109720102070D94` означает
  масштаб 1, 2 знака. Контрольная сумма `94` равна сумме предыдущих байтов по
  модулю 256. Масштаб 0 считается неразобранным ответом.
* События (стандарт MDB, **на адаптере не подтверждено**):
  `03 ХХХХ` начало сессии (доступная сумма), `05 ХХХХ` оплата одобрена
  (сумма), `06` отказ, `07` конец сессии, `08` отменено. Последний байт
  принимается как контрольная сумма, только если она сходится.
  Всё остальное помечается «не распознано», без догадок. Сырой вывод
  важнее разбора.
* Конец сообщения определяется по паузе **60 мс** без новых байтов. Если
  два события пришли быстрее, они склеятся в одну строку. Поэтому в
  журнале указано время первого байта и длительность приёма.

## Порядок проверки

1. Вставить адаптер в USB-порт планшета, терминал подключить к адаптеру
   (питание по инструкции Wafer и Nayax).
2. Сервисное меню (PIN) → «Терминал (стенд)» → **«Найти USB-устройства»**.
   В списке видны VID/PID, производитель, класс и найденный драйвер.
   Точный VID/PID адаптера **не подтверждён**. Ожидается FTDI FT232RL
   (VID 0403). Если драйвер «не найден», выберите его вручную в списке
   «Драйвер».
3. **«Открыть порт»**. Если разрешения на USB ещё нет, система покажет
   окно разрешения (см. «Разрешение на USB» ниже). После согласия порт
   откроется сам.
4. **setup** → дождаться ответа `01…` (на экране появятся масштаб и знаки).
5. **prices** → **enable**.
6. Приложить карту. Ожидается событие `03…` (начало сессии).
7. Сумма `0.10` → **«Запрос оплаты»**. Ожидается `05…` (одобрено) или
   `06` (отказ). **Списание реальное.**
8. **ok** → **done**. Ожидается `07` (конец сессии).
9. **disable** → **«Закрыть порт»**.

Если ответа нет, подождите и повторите команду: терминал мог быть занят.

## Журнал

* Строка журнала: время с миллисекундами, направление `->` (отправлено),
  `<-` (принято) или `**` (служебное), затем `hex`, `ascii`, сырые байты и
  разбор.
* В памяти хранятся последние 2000 строк. Кнопка «Очистить» чистит только
  экран, файл не трогает.
* **«Копировать журнал»** кладёт журнал в буфер обмена.
* Те же строки дописываются в файл
  `/sdcard/Android/data/ee.carfog.dryfog/files/mdb_bench.log`. Точный путь
  показан на экране. При 5 МБ файл переименовывается в `mdb_bench.log.1`.
* Журнал **в облако не уходит**.
* Как забрать файл: владелец открывает окно сетевого ADB («Облако» →
  «Сетевой ADB на 30 минут»), затем
  `adb pull /sdcard/Android/data/ee.carfog.dryfog/files/mdb_bench.log`.

## Разрешение на USB (не проверено на планшете)

* Приложение запрашивает доступ к адаптеру через `UsbManager.requestPermission`.
  Система показывает окно SystemUI.
* Покажется ли это окно под блокировкой (Lock Task + Device Owner),
  **не проверено**. Если окна нет, запасной путь такой: «Киоск» →
  временный выход из блокировки, затем «Открыть порт» и согласие в окне.
* Как получить разрешение без окна в боевой прошивке (user, без su),
  **не решено**. Публичного API Device Owner для этого нет.
* Реакция на `USB_DEVICE_ATTACHED` (автозапуск при подключении) намеренно
  не добавлена, чтобы подключение адаптера не поднимало окна в киоске.

## Чего не делать

* **Не вскрывать корпус терминала Nayax.** При срабатывании датчика
  вскрытия терминал блокируется навсегда.
* **Не менять настройку Syoung «OTG HOST»** (хост или устройство) на
  CARFOG-100: она может отключить USB-хост.
* Не гонять лишние запросы оплаты: каждое одобрение списывает деньги.
* Не оставлять терминал включённым (`enable`) без присмотра.
