# ТЗ: бренды дистрибьюторов (белый лейбл) v1

Статус: вопросы раздела 9 закрыты владельцем 2026-11-05; ТЗ ждёт его «да» на старт этапа 1 (база и Edge Function). Опора: опись `docs/inventory/brand_inventory.md` (ветка `inventory-brand-diag`, d4b5f30, код на ea5f87e). Ветка проекта: «ПО». Миграции применяются только после отдельного «да».

## 1. Цель
Одна сборка приложения для всех аппаратов. Внешний вид клиентских экранов (логотип, цвета, название, слоган, QR, контакты) определяется «пакетом бренда», который лежит в облаке и на аппарате. Обновление APK не должно менять бренд аппарата. Если пакета нет или он испорчен, аппарат показывает встроенный бренд CaRFog.

## 2. Решения владельца (уже приняты, 2026-11-03/04)
1. Бренд редактируем только мы по заказу дистрибьютора. Кабинет дистрибьютора — позже.
2. Выручка идёт конечному владельцу аппарата, он не обязательно дистрибьютор. «Продавец» на экране относится к конечному владельцу, а не к дистрибьютору и не к нам.
3. Подпись «Powered by CaRFog» маленькая, остаётся всегда, зашита в приложение.
4. Видео на SD-карте сначала одинаковое у всех, потом владельцы записывают своё сами (это не часть пакета бренда).
5. Письменное согласие дистрибьютора на использование его логотипа обязательно.
6. QR-код: единый новый QR CaRFog (carfog.eu, файл CaRFog_QR_carfog_eu_EN.svg, 2026-11-04) — «встроенный бренд по умолчанию». Ссылка QR принадлежит аппарату (владельцу), бренд даёт значение по умолчанию (подтверждено 2026-11-05).
7. Контакты продавца вводим мы при заказе (через супервайзера), клиенту в кабинете даём позже (подтверждено 2026-11-05).
8. Слоган бренда только на английском, одна строка для всех языков интерфейса (подтверждено 2026-11-05). Название бренда на заставке заменяет «CaRFog OÜ» полностью; внизу остаётся только «Powered by CaRFog» (подтверждено 2026-11-05).

## 3. Что входит в бренд, что нет
| Часть | Где хранится | Кто меняет |
|---|---|---|
| Логотип, цвета (токены), название бренда, слоган (английский) | пакет бренда (`brand_versions`) | мы (супервайзер) |
| QR заставки по умолчанию (картинка) | в пакете бренда | мы |
| Контакты продавца (телефон, почта, сайт, юр. строка), ссылка QR аппарата | данные аппарата (`app_config`, `update_config`) | мы при заказе; клиенту дать позже (вопрос 9.2) |
| Видео ожидания | SD-карта аппарата | владелец |
| Названия ароматов, цены, языки | уже данные аппарата | как сейчас |
| «Powered by CaRFog», смысловые цвета (ошибка, нагрев, предупреждение, обработка) | зашито | никто |
| Сервисное меню, экран PIN, раскладка, шрифты, размеры | зашито | никто |

Контакты и ссылка QR принадлежат аппарату, а не бренду: у каждого владельца свои. Бренд даёт только значения по умолчанию.

## 4. Токены цвета
Семь токенов бренда: `primary`, `primaryAlt` (два акцента), `background`, `backgroundStandby` (два фона), `surface`, `textPrimary`, `textSecondary`. Встроенный бренд CaRFog содержит ровно текущие значения (`#2EC4B6`, `#00C6B2`, `#1A1A1A`, `#0B2545`, `#2E2E2E`, белый, `#8899AA`), чтобы эталоны Syoung не менялись. Слить два акцента в один можно только по отдельному «да» с обновлением эталонов.
Контраст (WCAG): текст к фону не меньше 4,5; крупный текст и значки не меньше 3,0. Проверка в портале при сохранении (не прошёл: сохранить нельзя) и на аппарате при приёме (не прошёл: остаётся прежний бренд, событие в облако).

## 5. Пакет бренда
Архив (zip, до 1 МБ): `brand.json` + `logo.png` (до 300 КБ, PNG с прозрачностью, сторона до 1000 px) + `qr_default.png` (по желанию).
`brand.json` (схема версии 1):
```
{ "schema":1, "id":"acme", "version":3, "name":"ACME Clean",
  "colors":{"primary":"#..","primaryAlt":"#..","background":"#..","backgroundStandby":"#..","surface":"#..","textPrimary":"#..","textSecondary":"#.."},
  "slogan":"English slogan", "logo":"logo.png", "qr_default":"qr_default.png" }
```
Правила на аппарате: каталог `filesDir/brand/<id>-v<версия>/`, указатель `filesDir/brand/current.json` {id, version, sha256}. Распаковка во временную папку, проверка sha256 архива, схемы и контраста, затем атомарная смена указателя. Любая ошибка: остаётся прежний бренд (или встроенный `assets/brand/default/`). Без сети работает последний годный. Бренд переживает обновление APK и перезагрузку.

## 6. База (черновик, НЕ применять до «да»)
```
create table public.brands (
  id text primary key check (id ~ '^[a-z0-9][a-z0-9_-]{1,30}$'),
  name text not null,
  current_version int,
  created_at timestamptz not null default now()
);
create table public.brand_versions (
  brand_id text not null references public.brands(id),
  version int not null,
  sha256 text not null check (sha256 ~ '^[0-9a-f]{64}$'),
  size_bytes int not null check (size_bytes between 1 and 1048576),
  path text not null,               -- bucket brand-packs
  manifest jsonb not null,
  logo_consent boolean not null,    -- письменное согласие дистрибьютора
  consent_note text,                -- кто, когда, где лежит документ
  contrast_ok boolean not null,
  created_by uuid not null,
  created_at timestamptz not null default now(),
  primary key (brand_id, version)
);
alter table public.devices add column brand_id text references public.brands(id);
-- null = встроенный CaRFog
```
RLS: обе таблицы закрыты для anon и authenticated; доступ только через функции. Бакет Storage `brand-packs` закрытый (public=false). Согласие: `logo_consent=false` допустим только для встроенного CaRFog; для остальных функция создания версии отклоняет.
Функции:
- `supervisor_brand_list()`, `supervisor_brand_create_version(brand, manifest, sha256, size, path, consent, note)` (только супервайзер с 2FA; запись в `staff_audit`), `supervisor_brand_assign(device, brand|null)`, `supervisor_brand_preview(...)`.
- `device_brand_get(token, device)`: проверка токена по хешу; возвращает {id, version, sha256, url} (подписанная ссылка 5 минут на архив). Либо Edge Function `brand-url` по образцу `release-url`.
- `device_poll` отвечает дополнительным полем `brand: {id, version, sha256} | null`.
- `reported_config` получает `brand_id`, `brand_version`, `brand_state` (applied / failed:<причина>), портал показывает, что реально стоит.
Загрузка архива в бакет: Edge Function `brand-upload` (только супервайзер, aal2, проверка размера и sha256) или подписанная ссылка на загрузку. Выбор и обоснование: за исполнителем (ответ в опись).

## 7. Приложение
1. `ThemeExtension` с токенами; встроенный бренд = текущие значения.
2. Перевод клиентских экранов (заставка, выбор языка, выбор аромата, оплата, подготовка, обработка, «Готово», «Ошибка», «Временно не работает») и виджетов `LangSwitcher`, `CardHintBanner`, `FogBackground`, `PUi` на токены. Коммиты по одному экрану, после каждого эталоны Syoung совпадают без обновления.
3. Заставка: логотип/название из бренда; QR: если у аппарата задана ссылка, QR рисуется из неё (библиотека `qr_flutter`) с логотипом по центру, иначе картинка QR бренда, иначе встроенный QR CaRFog; блок контактов (если заданы); «Powered by CaRFog» всегда.
4. Сервис приёма бренда: опрос из `device_poll`, скачивание, проверки, переключение, события `brand_applied` / `brand_failed`.
5. Профили `ixp101m1` и `sy156-a510` одинаково; раскладку не менять.

## 8. Портал (только супервайзер с 2FA)
Раздел «Бренды»: список, создание версии (загрузка логотипа, ввод 7 цветов, слоганов), предпросмотр заставки в обоих профилях, автопроверка контраста, обязательный флажок и заметка о согласии на логотип, привязка к аппаратам, показ реально установленной версии (`brand_state`). Клиенту раздела нет.

## 9. Ответы владельца (2026-11-05)
1. QR: ссылка у аппарата, по умолчанию новый QR CaRFog. Да.
2. Контакты продавца: сначала мы, клиенту позже. Да.
3. Слоган: только на английском (один для всех языков). Если слогана у бренда нет, показывается встроенный `standby.subtitle` по языкам.

1. База и Edge Function (файлы, SQL-тесты прав; применяю я после «да»): 2–3 дня.
2. Приложение: токены, экраны, QR/контакты, приём бренда: 5–6 дней.
3. Портал «Бренды»: 2–3 дня.
4. Живая проверка на CARFOG-001: бренд ACME-тест, обновление APK с сохранением бренда, порча пакета, без сети, откат на CaRFog.
Приёмка: эталоны Syoung не изменены; контраст работает; бренд переживает обновление APK и перезагрузку; без согласия на логотип версия не создаётся; клиент не видит и не вызывает `supervisor_*`.
