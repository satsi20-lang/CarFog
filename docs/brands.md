## 1. Как устроено, в двух словах

Сборка приложения одна для всех аппаратов. Внешний вид клиентских экранов
(логотип, семь цветов, название, слоган) задаёт «пакет бренда» — zip-архив
до 1 МБ, который лежит в закрытом хранилище и скачивается аппаратом. Если
пакета нет или он испорчен, аппарат показывает встроенный бренд CaRFog из
`assets/brand/default/`. Подпись «Powered by CaRFog» зашита в приложение и
остаётся всегда.

Контакты продавца и ссылка QR принадлежат **аппарату**, а не бренду: у
каждого владельца свои. Бренд даёт только значения по умолчанию.

## 2. Что где лежит

| Что | Где |
|---|---|
| Бренды и их версии | таблицы `public.brands`, `public.brand_versions` |
| Какой бренд у аппарата | `public.devices.brand_id` (null = встроенный CaRFog) |
| Архивы пакетов | закрытый бакет Storage `brand-packs`, путь `<бренд>/v<версия>.zip` |
| Встроенный бренд | в сборке приложения, `assets/brand/default/` |
| Видео ожидания | SD-карта аппарата (частью пакета бренда НЕ является) |

Служебная запись `brands('carfog','CaRFog')` есть всегда и версий не имеет:
встроенный бренд живёт в приложении. Загрузить версию для `carfog`
функция отказывается.

## 3. Формат пакета бренда

Архив zip, до 1 МБ, без каталогов. Допустимы ровно три имени:

* `brand.json` — обязателен;
* `logo.png` — обязателен, до 300 КБ, PNG, сторона до 1000 px;
* `qr_default.png` — по желанию, те же пределы.

`brand.json`, схема версии 1 (точно по ТЗ, раздел 5):

```json
{ "schema":1, "id":"acme", "version":3, "name":"ACME Clean",
  "colors":{"primary":"#..","primaryAlt":"#..","background":"#..","backgroundStandby":"#..","surface":"#..","textPrimary":"#..","textSecondary":"#.."},
  "slogan":"English slogan", "logo":"logo.png", "qr_default":"qr_default.png" }
```

Правила:

* `id` — по шаблону `^[a-z0-9][a-z0-9_-]{1,30}$`, обязан совпадать с тем,
  что просили при загрузке; то же про `version`.
* `name` — 1…40 символов, без управляющих символов. На заставке заменяет
  «CaRFog OÜ» полностью.
* `slogan` — только на английском, одна строка для всех языков, до 80
  символов. Пустой допустим: тогда аппарат покажет встроенную подпись
  `standby.subtitle` по языкам.
* `colors` — ровно семь токенов, каждый `#RRGGBB`. Лишний токен — отказ.
* Смысловые цвета (ошибка, нагрев, предупреждение, обработка), сервисное
  меню, раскладка, шрифты и размеры брендом не меняются.

### Проверка контраста (WCAG)

Единый источник правил — `supabase/functions/_shared/brand_rules.ts`.
Портал (этап 3) и приложение (этап 2) обязаны повторить ровно эти пороги.

| Пара | Не меньше |
|---|---|
| `textPrimary` к `background` | 4,5 |
| `textPrimary` к `surface` | 4,5 |
| `textPrimary` к `backgroundStandby` | 4,5 |
| `textSecondary` к `background` | 3,0 |
| `primary` к `background` | 3,0 |

Не прошло — версия не создаётся вовсе (`contrast_ok=true` требуется и
ограничением таблицы). Встроенные значения CaRFog эти пороги проходят, это
проверяется тестом `brand_rules_test.ts`.

### Согласие на логотип

Письменное согласие дистрибьютора обязательно (решение владельца 5).
`logo_consent=true` и непустая заметка `consent_note` (кто дал, когда, где
лежит документ) требуются и в Edge Function, и в функции базы, и
ограничением таблицы. Исключение одно — встроенный `carfog`.

## 4. Как это работает на аппарате

1. `device_poll` в каждом ответе отдаёт поле `brand: {id, version, sha256} | null`
   (рядом с `target`, как цель раскатки). Старые приложения это поле просто
   не читают.
2. Увидев другую версию, аппарат вызывает Edge Function `brand-url`
   (`{device, token}`) и получает подписанную ссылку на архив на 5 минут.
   Не чаще одного раза в 30 с на аппарат.
3. Аппарат скачивает архив, сверяет sha256, распаковывает в
   `filesDir/brand/<id>-v<версия>/`, проверяет схему и контраст и только
   потом атомарно переписывает указатель `filesDir/brand/current.json`.
4. Любая ошибка — остаётся прежний бренд (или встроенный CaRFog). Без сети
   работает последний годный. Бренд переживает обновление APK и перезагрузку.
5. Что реально установилось, аппарат сообщает в `reported_config`
   (`brand_id`, `brand_version`, `brand_state` = `applied` или
   `failed:<причина>`), и портал это показывает.

Пункты 2–5 — это **этап 2**, в приложении их ещё нет.

## 5. Как загружается новая версия (этап 3, портал)

Загружает только супервайзер с 2FA, через Edge Function `brand-upload`:

```
POST /functions/v1/brand-upload
Authorization: Bearer <JWT супервайзера, aal2>
{"brand":"acme","version":3,"consent":true,
 "consent_note":"кто дал, когда, где лежит документ",
 "zip_base64":"<архив до 1 МБ>"}
```

Почему тело JSON с base64, а не подписанная ссылка на загрузку: ссылка дала
бы браузеру право писать в бакет **до** проверки содержимого, и zip-бомба
или пакет без согласия уже лежали бы в хранилище. Здесь архив попадает в
бакет только после того, как функция сама посчитала sha256, распаковала его
в памяти с пределами, проверила схему, картинки, контраст и согласие. Прав
на Storage браузер не получает вообще.

Что проверяется по порядку: супервайзер с aal2 → согласие и заметка →
размер архива → sha256 (считаем сами, присланному не верим) → разбор zip
(не больше 8 файлов, только имена из белого списка, без путей и `..`,
суммарный распакованный размер до 3 МБ) → `brand.json` по схеме 1 → PNG
логотипа и QR → контраст → загрузка файла в бакет → запись версии. Если
запись не прошла, файл из бакета удаляется: мусора не остаётся.

Версия растёт строго на 1. Повтор уже существующей версии — отказ
(`conflict`), чтобы нельзя было подменить архив, который аппараты уже
скачали. Какая версия считается текущей, задаёт
`supervisor_brand_set_current` — откат на старую версию допустим.

### CORS

Функцию вызывает браузер портала, поэтому `brand-upload` отвечает на
предзапрос `OPTIONS` (204) и ставит заголовки CORS на **все** ответы,
включая ошибки: иначе портал увидел бы «ошибка сети» вместо причины
отказа. Разрешённые адреса перечислены в
`supabase/functions/_shared/cors.ts`:

* `https://app.carfog.online` — портал;
* `http://localhost:5173` — разработка.

Звёздочки (`*`) там нет и быть не должно: функция работает под JWT
супервайзера, открывать её любому сайту нельзя. Чужой Origin получает
ответ без `Access-Control-Allow-Origin`, и браузер сам его отбрасывает.
Если адрес портала сменится, его нужно добавить в этот список и
развернуть функцию заново.

`brand-url` вызывает аппарат, а не браузер: CORS там не нужен и не
добавлен.

### Если архив остался в бакете без записи в базе («сирота»)

Редкий случай: файл загрузился, а запись версии не прошла и убрать файл
тоже не удалось (например, оборвалась сеть). Функция чинит это сама:
перед загрузкой она спрашивает базу, есть ли такая версия, и если файл
уже лежит, а записи нет — перезаписывает его. Перезапись разрешена
**только** в этом случае; если версия в базе есть, ответ `conflict` и
архив не трогается.

По той же причине файл после неудачной регистрации удаляется только
тогда, когда версии в базе действительно нет: иначе можно было бы стереть
архив, на который уже ссылается чужая запись.

Остаточный риск: если два супервайзера одновременно загружают один и тот
же бренд и номер версии, проигравший может успеть перезаписать архив
победителя. Тогда контрольная сумма в базе не сойдётся с файлом, аппарат
откажется принимать пакет и сообщит `brand_failed`. Это видно в портале и
лечится загрузкой следующей версии; молча испорченных данных не будет.
Чтобы случая не было вовсе, не загружайте один бренд с двух мест
одновременно.

Если функция всё же отвечает `conflict` с `details: "already_uploaded"`
или `"busy"` и загрузить версию не получается: в Supabase → Storage →
`brand-packs` удалить файл `<бренд>/v<версия>.zip` вручную (убедившись,
что в таблице `brand_versions` такой версии нет) и повторить загрузку.

## 6. Функции базы

Для супервайзера с 2FA (проверка `_diag_supervisor_denied()` из RD1):

* `supervisor_brand_list()` — бренды, их версии, число привязанных аппаратов.
* `supervisor_brand_preview(бренд, версия)` — манифест версии (цвета,
  название, слоган) для предпросмотра заставки.
* `supervisor_brand_assign(аппарат, бренд)` — привязка; `null` или
  `'carfog'` снимает бренд и возвращает аппарат на встроенный CaRFog.
* `supervisor_brand_set_current(бренд, версия)` — какая версия текущая.
* `supervisor_brand_check()` — «это супервайзер с 2FA?» и кто именно;
  её вызывает `brand-upload` под JWT вызывающего.

Только сервисный ключ (Edge Functions):

* `_brand_version_register(...)` — запись версии после всех проверок.
* `device_brand_path(бренд, версия)` — путь архива в бакете.

Для аппарата (`anon` и сервисный ключ, как остальные `device_*`):

* `device_brand_get(аппарат, токен)` — какой бренд положен; ссылку НЕ
  отдаёт и путь в бакете не раскрывает. Лимит: раз в 30 с на аппарат.
* `device_poll(...)` — пересоздана: добавлено поле `brand`, остальное
  слово в слово как было.

В `staff_audit` пишутся действия `supervisor_brand_create_version`,
`supervisor_brand_assign`, `supervisor_brand_set_current`.

### Почему у бакета `brand-packs` нет ни одной политики

У бакета диагностических снимков есть политика чтения для супервайзера с
2FA: порталу нужно показать картинку. Пакету бренда это не нужно. При
создании версии логотип лежит у супервайзера в браузере — он сам его
только что выбрал, предпросмотр рисуется из этого файла и семи цветов. Для
уже созданной версии порталу хватает манифеста из
`supervisor_brand_preview`. Архив целиком нужен только аппарату, и он
получает его по подписанной ссылке от `brand-url`. Поэтому у бакета нет
политик вовсе: ни anon, ни authenticated, ни супервайзер не трогают файлы
напрямую — только сервисный ключ внутри двух Edge Functions.

Если позже в портале понадобится показывать логотип уже загруженной
версии, это добавляется веткой для супервайзера в `brand-url` (нужно
отдельное «да»), а не политикой на бакет.

## 7. Порядок применения (для владельца)

Делать по очереди, каждый шаг проверять. Миграция сама создаёт бакет, так
что руками в Supabase ничего настраивать не нужно.

1. **Миграция.** В Supabase → SQL Editor выполнить целиком файл
   `supabase/migrations/20261106000000_brand1_brands.sql`.
   Проверить, что появились таблицы `brands`, `brand_versions`,
   `brand_url_requests`, колонка `devices.brand_id` и бакет `brand-packs`
   (Storage → он должен быть **не публичный**).
2. **Проверка прав.** На тестовом проекте (или копии) выполнить
   `supabase/tests/rls_brands.sql`, подставив свои `<SUPERVISOR_UUID>`,
   `<CUSTOMER_UUID>`, `<DEVICE_ID>`, `<DEVICE_TOKEN>`. В «Messages» не
   должно быть ни одной строки «ОШИБКА». Файл заканчивается `rollback` —
   данные не остаются. **На рабочей базе не запускать.**
3. **Edge Functions.** Из папки проекта:
   ```
   supabase functions deploy brand-url --no-verify-jwt
   supabase functions deploy brand-upload
   ```
   Разница важна. `brand-url` вызывает аппарат с публичным ключом (это не
   JWT), поэтому `--no-verify-jwt`, а подлинность проверяет токен внутри.
   `brand-upload` вызывает супервайзер из портала со своим JWT — флаг НЕ
   нужен, пусть платформа отклоняет вызовы без входа.
   Секретов задавать не нужно: `SUPABASE_URL`, `SUPABASE_ANON_KEY` и
   `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам.
   Перед развёртыванием `brand-upload` проверить, что адрес портала есть в
   списке `ALLOWED_ORIGINS` в `supabase/functions/_shared/cors.ts`
   (см. «CORS» выше).
4. **Проверка вживую** — только когда будет готов этап 3 (портал) или
   вручную curl'ом: загрузить тестовый бренд `acme-тест`, привязать к
   `CARFOG-001`, убедиться, что `device_poll` отдаёт `brand`.

## 8. Как откатить

Безопасный откат по шагам, от меньшего к большему.

1. **Снять бренд с аппаратов** — аппараты вернутся на встроенный CaRFog,
   ничего больше менять не нужно:
   ```sql
   update public.devices set brand_id = null;
   ```
2. **Убрать поле `brand` из `device_poll`** — выполнить заново тело
   функции из `supabase/migrations/20261018000000_token_hash_phase_a.sql`
   (раздел `device_poll`). Приложения, которые поля ещё не знают, от этого
   не страдают.
3. **Выключить Edge Functions**: `supabase functions delete brand-url` и
   `supabase functions delete brand-upload`.
4. **Удалить таблицы и бакет** (только если точно решено отказаться; это
   уничтожает архивы и записи о согласиях):
   ```sql
   alter table public.devices drop column if exists brand_id;
   drop function if exists public.device_brand_get(text, text);
   drop function if exists public.device_brand_path(text, int);
   drop function if exists public._brand_for_device(text);
   drop function if exists public._brand_version_register(
     text, text, int, text, int, text, jsonb, boolean, text, boolean, uuid);
   drop function if exists public.supervisor_brand_list();
   drop function if exists public.supervisor_brand_preview(text, int);
   drop function if exists public.supervisor_brand_assign(text, text);
   drop function if exists public.supervisor_brand_set_current(text, int);
   drop function if exists public.supervisor_brand_check();
   drop table if exists public.brand_versions;
   drop table if exists public.brands;
   drop table if exists public.brand_url_requests;
   -- файлы бакета сначала удалить в Storage, затем:
   delete from storage.buckets where id = 'brand-packs';
   ```
   Шаг 4 необратим. Записи о согласии на логотип — юридически значимые,
   перед удалением сохранить выгрузку `brand_versions`.

## 9. Проверки кода

```
node --test supabase/functions/_shared/brand_rules_test.ts
node --test supabase/functions/_shared/cors_test.ts
node --test supabase/functions/brand-url/logic_test.ts
node --test supabase/functions/brand-upload/logic_test.ts
```

Архивы для проверок собираются в самих тестах настоящим мини-записывателем
zip, поэтому проверяется именно чтение формата: хороший архив, zip-бомба (и
честная, и врущая о размере), лишние файлы, путь `../x`, не PNG, слишком
большой логотип, плохой контраст, отсутствие согласия, чужая версия, не
супервайзер, отсутствие 2FA. Отдельно проверены CORS (предзапрос со своего
и с чужого адреса, заголовки на ответах об ошибках) и решения про
«сироту» в бакете.

Секретов, токенов и ключей в этих файлах нет и быть не должно.
