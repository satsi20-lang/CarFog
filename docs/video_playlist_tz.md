# ТЗ: видео заставки через портал (плейлист с галочками) v1

Ветка проекта: «ПО». Решения владельца 2026-11-07. Миграции и развёртывание — только после отдельного «да» владельца (применяет ассистент). Установка на планшеты — только по «да».

## 1. Цель
Владелец аппарата (клиент) и супервайзер загружают видео заставки через портал. Аппарат скачивает их на SD-карту один раз и хранит. В портале виден список всех видео на планшете (в том числе положенных на карту вручную); галочкой «Проигрывать» выбирается, какие играют на заставке (например, рекламные ролики ароматов). Смена набора не требует повторной закачки. Видео можно удалить с планшета.

## 2. Решения владельца
1. Без перекодирования на сервере. Формат указан в инструкции; ответственность за содержание (права, законность) — на владельце аппарата.
2. Сервер проверяет формат по содержимому файла (не только по расширению): MP4, видеодорожка H.264, разрешение под профиль планшета: `ixp101m1` — 1280×800 (альбом), `sy156-a510` — 1080×1920 (портрет). Звук: в инструкции «без звука»; если звуковая дорожка есть — файл принимается, на аппарате играет без звука по текущей настройке «Звук видео ожидания» (решение исполнителя, можно поменять).
3. Без лимитов размера и длительности с нашей стороны (остаются технические пределы хранилища Supabase и места на SD).
4. Порядок проигрывания не настраивается (без перетаскивания): играют отмеченные по кругу в порядке даты добавления.
5. Если ни одно видео не отмечено — играет встроенное видео CaRFog по умолчанию.
6. Видео, уже лежащие на SD-карте (положенные вручную), показываются в списке, ими можно управлять (галочка; удаление — если Android даёт приложению удалить этот файл).
7. Загружать может клиент (только для своих аппаратов) и супервайзер с 2FA (любой аппарат). Каждое действие пишется в журнал (кто, когда, какой файл).
8. Супервайзер может снять/удалить любое видео с любого аппарата («Убрать видео»).

## 3. Облако
### 3.1 Хранилище
Закрытый бакет `device-videos` (public=false), тип `video/mp4`, без политик для anon/authenticated: загрузка только по одноразовой подписанной ссылке на загрузку (выдаёт Edge Function), скачивание аппаратом — по подписанной ссылке (Edge Function). Путь `<device_id>/<video_id>.mp4`. Если глобальный предел размера файла проекта меньше файла — понятное сообщение в портале.

### 3.2 Таблица `device_videos`
`id uuid`, `device_id`, `org_id`, `title` (имя для показа, ≤ 120), `source` (`upload` | `sd_local`), `storage_path` (null для `sd_local`), `local_name` (имя файла на SD, для `sd_local` и после скачивания), `sha256` (64 hex; для upload — считает браузер потоково), `size_bytes` (bigint), `width`, `height`, `duration_ms`, `has_audio`, `status` (`pending_upload` | `validating` | `rejected` | `ready` | `on_device` | `failed` | `delete_requested` | `deleted`), `reject_reason`, `play boolean default false`, `device_state` (что сообщил аппарат: `downloading` | `present` | `failed:<причина>` | `missing`), `created_by uuid`, `created_at`, `updated_at`. RLS включён, прямого доступа у anon/authenticated нет, только через функции.
Счётчик `devices.videos_rev int` — растёт при любом изменении желаемого состояния (галочки, новое видео, удаление); `device_poll` отдаёт `videos_rev` (не меняя остальные поля).

### 3.3 Функции базы (security definer, search_path=public)
Права: клиент — `customer_has_access(p_device)`; супервайзер — `_diag_supervisor_denied() is null`. Журнал: `staff_audit_add` (для клиента — отдельная запись в своей таблице аудита или в `staff_audit` с пометкой роли; исполнитель выбирает и объясняет).
- `video_list(p_device)` → список строк для портала (без storage_path).
- `video_upload_begin(p_device, p_title, p_size, p_sha256)` → создаёт строку `pending_upload`, возвращает `video_id` (ссылку на загрузку выдаёт Edge Function).
- `video_set_play(p_video, p_play)`; `video_delete(p_video)` (→ `delete_requested`, если на аппарате; иначе `deleted` и удаление объекта).
- `_video_mark_validated(...)` / `_video_mark_rejected(...)` — только service_role (вызывает Edge Function проверки).
- `device_videos_get(p_device, p_token)` (anon+service_role, токен по хешу, лимит частоты 30 с) → желаемое состояние: список `{id, title, sha256, size_bytes, play, delete}` + `videos_rev`.
- `device_video_report(p_device, p_token, p_items jsonb)` → аппарат сообщает фактический список: скачанные (`id`, `state`), локальные файлы с SD (`local_name`, размер, ширина/высота/длительность, можно ли удалить) — для новых локальных создаются строки `sd_local`; пропавшие помечаются `missing`. Лимиты: ≤ 200 элементов, размеры полей.

### 3.4 Edge Functions
- `video-upload-url` (JWT, CORS только `https://app.carfog.online` и `http://localhost:5173`): проверка прав через функцию под JWT вызывающего; выдаёт одноразовую подписанную ссылку на загрузку `createSignedUploadUrl` для `video_id` в статусе `pending_upload`.
- `video-validate` (JWT, CORS): после загрузки браузером — проверка содержимого БЕЗ скачивания всего файла: чтение диапазонами (начало и конец файла) и разбор MP4-боксов: `ftyp`, `moov` (может быть в конце) → `mvhd` (длительность), `trak`/`tkhd` (ширина/высота), `hdlr` `vide`/`soun`, `stsd` `avc1`/`avc3` (H.264). Сравнение размера с объявленным. Проверка разрешения под `hardware_profile` аппарата. Не подошло — объект удаляется, статус `rejected` с понятной причиной. Подошло — `ready`, `videos_rev++`.
- `video-url` (без JWT, как `brand-url`): по токену аппарата — подписанная ссылка на скачивание (срок достаточный для большого файла, например 6 часов; исполнитель обоснует).
- Уборка: объект в бакете удаляется при `deleted` (сразу или pg_cron раз в сутки — исполнитель предлагает).

## 4. Приложение
1. Опись (первый шаг): где сейчас лежит и как ищется видео заставки на SD (путь, права Android 13), как работает плеер и настройка звука. Если файлы в корне карты — показать их как `sd_local`; удалять только если есть права, иначе в портале «удалить нельзя».
2. Новые видео хранятся в папке приложения на SD (`getExternalFilesDirs` для съёмной карты; без новых разрешений). Скачивание: проверка свободного места (новый файл + запас) до начала, загрузка во временный файл с докачкой при обрыве (Range), проверка размера и sha256, проверка воспроизводимости (открыть плеером/MediaMetadataRetriever, прочитать кадр), затем атомарное переименование. Любая ошибка — файл удаляется, `failed:<причина>` в отчёт, проигрывание не страдает.
3. Синхронизация: при изменении `videos_rev` из `device_poll` — `device_videos_get`, скачать недостающие (по одному), удалить помеченные, отправить `device_video_report`. Отчёт также при старте и раз в сутки. Скачивание не мешает обслуживанию клиента (низкий приоритет, пауза во время цикла — по усмотрению исполнителя с обоснованием).
4. Проигрывание на заставке: отмеченные (`play=true`) и присутствующие на карте — по кругу в порядке даты добавления; если ни одного — встроенное видео CaRFog. Переключение набора — без перезапуска приложения, без чёрного экрана (смена на границе ролика).
5. Звук — по существующей настройке «Звук видео ожидания».
6. Пакет диагностики: блок `videos` (число, состояние, свободное место, последняя ошибка), без ссылок и токенов.
7. Оба профиля одинаково; раскладку и эталоны не менять.

## 5. Портал
Страница аппарата → блок «Видео» (клиенту для своих аппаратов, супервайзеру для всех):
- таблица: название, источник (загружено / на карте), размер, длительность, разрешение, состояние на аппарате (скачивается / есть / ошибка / нет), галочка «Проигрывать», кнопка «Удалить»;
- загрузка: выбор файла → предварительная проверка в браузере (расширение, MP4-заголовок, разрешение если читается) → sha256 потоково (библиотека в бандле, не CDN) → `video_upload_begin` → ссылка → загрузка с прогрессом → `video-validate` → результат;
- подсказка с форматом из инструкции; понятные сообщения об отказе;
- подпись: «Если ничего не отмечено, играет стандартное видео CaRFog»;
- i18n EN/RU/ET; CSP: разрешить загрузку в хранилище Supabase (`connect-src` уже содержит домен проекта — проверить).

## 6. Этапы
1. Опись приложения (видео, SD, права) — 0,5 дня.
2. База и Edge Functions (файлы, тесты) — 2 дня.
3. Портал — 2 дня.
4. Приложение — 3–4 дня.
5. Живая проверка на CARFOG-001 по «да»: загрузка верного и неверного файла, галочки, смена набора без закачки, удаление, ручной файл на карте, нехватка места, обрыв сети при скачивании, ничего не отмечено → встроенное видео.

## 7. Инструкция для клиента (текст в портале и документации)
Формат: MP4, видео H.264, без звука, 1280×800 (альбом, малый планшет) или 1080×1920 (портрет, основной планшет). Размер и длительность не ограничены, но большие файлы дольше скачиваются и тратят мобильный трафик. За содержание видео (права на изображение и музыку, законность) отвечает владелец аппарата; CaRFog вправе удалить видео без предупреждения.
